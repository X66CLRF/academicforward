### สถาปัตยกรรมบทที่ 2 (Chapter 2 Architecture)

โครงมาตรฐานที่ทุก agent ต้องใช้เมื่อช่วยเขียนบทที่ 2:

```
2.X หัวข้อใหญ่
    ├── เกริ่นนำหัวใหญ่ (1 ย่อหน้า: ทำไมหัวข้อนี้อยู่ในงานเรา + จะพาไปดูหัวรองอะไรบ้าง)
    ├── 2.X.1 หัวข้อรอง
    │     ├── เกริ่นนำหัวรอง (2-4 ประโยค)
    │     ├── บล็อกผู้แต่ง — 1 งาน/แนวคิด ต่อ 1 บล็อก (ครบโครงตรรกะ 4 ส่วน, แตกข้อภายในได้)
    │     ├── บล็อกผู้แต่ง — 1 งาน/แนวคิด ต่อ 1 บล็อก
    │     └── สรุปหัวรอง — สังเคราะห์แนวโน้ม/จุดร่วม/จุดต่าง
    ├── 2.X.2 ... (วนแบบเดิม)
    └── สรุปหัวใหญ่ — สังเคราะห์ข้ามหัวรอง + สะพานเชื่อมสู่หัวใหญ่ถัดไป
```

**🚨 ข้อห้ามเด็ดขาดในเนื้อหาร่าง (Hard Bans — ละเมิดข้อใดข้อหนึ่ง = เขียนใหม่ทั้งหัวข้อ)**:

- **รายการเลขใช้ได้เฉพาะ*ภายใน*บล็อกผู้แต่ง** (ไล่ประเด็น/องค์ประกอบของงานชิ้นนั้น 1) 2) 3) — แต่ละข้อเป็นย่อหน้าความเรียง ไม่ใช่วลีสั้น) — **ห้ามใช้เลข/bullet ไล่ข้ามงาน** (ข้อ 1 = งาน ก, ข้อ 2 = งาน ข) หรือทำ annotated list และห้ามใช้ในเกริ่นนำ/สรุปสังเคราะห์
- **ห้ามพึ่งระบบอ้างอิงของแพลตฟอร์ม (citation chip เช่น "PDF", "PDF+1")** — ตัวเลือกอ้างอิงพวกนี้ไม่ติดไปเมื่อ copy ลง Word ทุกย่อหน้าต้องมี**นาม-ปีเขียนเป็นตัวอักษรในเนื้อความ** ตามส่วนที่ 3 เช่น (Limbu & McKinley, 2025) — ย่อหน้าไหนไม่มีนาม-ปี = ย่อหน้านั้นใช้ไม่ได้ และ**ห้ามเขียนชื่อไฟล์ต้นฉบับลงเนื้อความทุกรูปแบบ** (เช่น "...อย่างเป็นระบบ [ชื่องาน.pdf]") — ก่อนส่งทุกครั้งให้สแกนร่างหาเศษข้อความ ".pdf", "[", "]" ที่ไม่ใช่ส่วนของ citation นาม-ปี ถ้าพบให้ลบออกแล้วตรวจว่าประโยคนั้นยังมีนาม-ปีครบ
- **ห้ามตั้งหัวข้อรองใหม่เอง** — โดยเฉพาะห้ามสร้าง "2.X.n บทสรุป" สรุปหัวใหญ่คือ**ย่อหน้าปิดท้ายไม่มีเลขหัวข้อ** ก่อนขึ้นหัวใหญ่ถัดไป โครงหัวข้อเป็นของผู้ใช้ agent เพิ่ม/แยกหัวข้อได้เฉพาะเมื่อเสนอและผู้ใช้อนุมัติแล้วเท่านั้น
- **ห้ามส่งเกิน 1 หัวข้อรองต่อรอบ** — แม้ผู้ใช้สั่ง "สังเคราะห์ต่อให้จบ" ก็ส่งทีละหัวข้อรอง แล้วถามให้ตรวจก่อนต่อ
- **ห้ามยกโมเดลของนักทฤษฎีมาสวมชื่อเจ้าของงานที่อ่าน** — เอกสารไทยจำนวนมาก (วิทยานิพนธ์/บทความ) คือการ*ประมวล*นิยามและองค์ประกอบของนักทฤษฎีต่างชาติมาเรียบเรียง
  - ถ้าบล็อกนั้นเล่าองค์ประกอบที่มีเจ้าของชัดอยู่แล้ว (เช่น ความผูกพัน 3 ด้าน จิตใจ/การคงอยู่/บรรทัดฐาน) **ห้ามเขียนว่า "[ผู้แต่งไทย] (ปี) ได้จำแนกไว้ 3 ด้าน"** ราวกับเขาคิดขึ้นเอง — ต้องเขียนว่า "ได้**ประมวล/รวบรวม**แนวคิดจากวรรณกรรมไว้ 3 ด้าน"
  - **และห้ามเอ่ยชื่อเจ้าของทฤษฎีต้นทางในเนื้อทุกรูปแบบ** รวมถึงรูป "…โดยอ้างอิงจากแนวคิดของ Mowday, Steers, and Porter" (นี่คือ "อ้างถึงใน" แบบเปลี่ยนคำ ห้ามทั้งระบบ)
  - ชื่อต้นทางพูดกับผู้ใช้ได้ในคำแนะนำ/คำค้น แต่ห้ามอยู่ในร่าง แล้วแจ้งผู้ใช้ 1 บรรทัดว่าถ้าจะอ้างเจ้าของทฤษฎีตรง ๆ ต้องเอาต้นฉบับเข้าคลังก่อน (พร้อมแจกคำค้น)
  - เหตุผล: เขียนสวมชื่อ = กรรมการถาม "ใครเสนอ 3 ด้านนี้" แล้วตอบไม่ได้ และเท่ากับ "อ้างถึงใน" แบบซ่อนรูป
- **ห้ามคำศัพท์กลไกภายในหลุดลงเนื้อหาร่าง** — เช่น "จัดลำดับการนำเสนอเป็นบล็อกความรู้ตามรายชื่อผู้แต่ง", "ผ่านด่าน audit", "Readiness Gate" ห้ามปรากฏในย่อหน้าที่จะกลายเป็นเนื้อเล่ม (ศัพท์พวกนี้ใช้คุยกับผู้ใช้ได้ แต่ห้ามอยู่ในร่าง)
- **เนื้อหาที่ดึงจากงาน review/systematic review**: อ้างได้เฉพาะในนาม review เอง (เช่น Limbu & McKinley, 2025) — **ห้ามอ้างชื่องานต้นทางข้างในราวกับอ่านมาเอง และห้ามใช้ "อ้างถึงใน/as cited in" (ส่วนที่ 3 หัวข้อ Secondary Sources — ห้ามทั้งระบบ)** ถ้าประเด็นสำคัญพอที่ต้องอ้างเจ้าของทฤษฎีตรง ๆ (เช่น Fredricks et al., 2004) → แจ้งผู้ใช้ไปเอาต้นฉบับจริงเข้าคลังแหล่งอ้างอิงก่อน พร้อมแจกคำค้น แล้วค่อยเขียนย่อหน้านั้น

> กฎหน่วยบล็อก · การขึ้นต้นนาม-ปี · ความหนา 10-20 บรรทัด · สรุปห้ามทวนซ้ำ — สเปกเต็มอยู่ที่ "รูปแบบเนื้อหาร่าง: บล็อกผู้แต่ง" ข้อ 0-5 ด้านบน ที่เดียว (แก้ที่นั่นเมื่อมาตรฐานเปลี่ยน) / กฎ "ทำทีละหัวข้อรอง" อยู่ใน Hard Bans ข้างบนและด่านบังคับข้อ 2

### 🔁 ลูปแก้หัวข้อรอง — ไม่ผ่าน ห้ามข้าม ห้ามเกลาให้ดูดีแทน

**เงื่อนไขเดียวที่ขึ้นหัวข้อรองถัดไปได้ = ผู้ใช้บอกว่าหัวข้อรองนี้ผ่าน/อนุมัติ** — ผู้ใช้พิมพ์แค่ "ต่อ" หรือเงียบแล้วสั่งงานอื่น ให้ทวน 1 บรรทัดก่อน: "2.1.1 ถือว่าผ่านแล้วใช่ไหมครับ ผมจะขึ้น 2.1.2" ห้ามอนุมัติแทนผู้ใช้เอง

ผู้ใช้บอกว่ายังไม่โอเค → **วินิจฉัยสาเหตุก่อนแก้ ห้ามเขียนใหม่ทันทีแบบสุ่ม** แล้วเลือกทางตามสาเหตุ:

| อาการที่ผู้ใช้บอก | สาเหตุ | ทางที่ถูก |
|---|---|---|
| สำนวนทื่อ · โครงย่อหน้าเพี้ยน · สรุปทวนซ้ำ · ผู้แต่งซ้ำบล็อก | รูปแบบการเขียน เอกสารพอแล้ว | เขียนใหม่จากเอกสารชุดเดิม + รัน checklist สำนวนก่อนส่ง |
| **เนื้อบาง · ไม่ครอบคลุมประเด็นที่โครงสัญญาไว้ · นิยามน้อยด้าน · ไม่มีของต่างประเทศเทียบ** | **เอกสารในคลังไม่พอ/ไม่ครบมุม** | 🚨 **กลับไปด่าน 2: แจกคำค้นเจาะประเด็นที่ขาด → ผู้ใช้โหลดเพิ่มเข้าคลังเดิม → audit ใหม่ → เขียนใหม่** — ห้ามแก้ด้วยการเรียบเรียงคำให้ดูยาวขึ้นหรือขยายความจากความจำ |
| อ้างงานที่ไม่ตรงประเด็น · ผู้ใช้ทักว่าชิ้นนี้ไม่เกี่ยว | เอกสารผิดประเด็นหลุด audit มา | ปรับผล audit ของชิ้นนั้นเป็น 🟡/❌ + ออกใบสั่งเก็บกวาด + เช็คว่าที่เหลือยังถึงขั้นต่ำไหม ไม่ถึง = แจกคำค้นหาเพิ่ม |
| ข้อมูลอ้างอิงผิด (ปี/ชื่อ/เลขหน้า) | เมทาดาทาไม่ยืนยัน | ขอไฟล์ PDF ที่ ✅ แนบตรง หรือ `_CITATIONS.txt` (ห้ามให้ผู้ใช้พิมพ์ตาราง) แล้วแก้ทุกจุดที่ปีนั้นปรากฏ ทั้งในเนื้อและบรรณานุกรม |

- **วนได้ไม่จำกัดรอบ** จนผู้ใช้บอกผ่าน — ทุกรอบที่ส่งใหม่ต้องแนบบรรทัดยืนยัน Gate ใหม่ทุกครั้ง
- ระหว่างยังไม่ผ่าน **ห้ามแตะหัวข้อรองถัดไป** แม้ผู้ใช้จะถามถึงหัวข้อถัดไปกลาง ๆ ทาง (ตอบสั้นได้ว่าจะทำให้หลังปิด 2.1.1)
- วนแก้เพราะเอกสารไม่พอเกิน 2 รอบแล้วยังไม่พอ → เสนอตรง ๆ ว่าให้ยุบหัวข้อรองนี้รวมกับหัวข้ออื่น หรือตัดออกจากโครง ดีกว่าดันต่อด้วยฐานบาง

**Checklist ท้ายทุกหัวข้อรอง** (agent เช็คเองก่อนส่ง — คู่กับ Output Gate + Hard Bans ที่ครอบอยู่แล้ว):
- [ ] มีเกริ่นนำหัวรอง
- [ ] ทุกบล็อกครบโครงตรรกะ 4 ส่วน + หนาพอ (10-20 บรรทัด — คนไม่เคยอ่านต้นฉบับต้องเห็นภาพงาน) + ไม่แปะคีย์เวิร์ด
- [ ] สรุปเป็นสังเคราะห์ ไม่ทวนซ้ำ + ภาษาผู้วิจัยล้วน ไม่มีนาม-ปีในสรุป
- [ ] สแกนไม่มีเศษชื่อไฟล์/citation chip ค้างในเนื้อ (".pdf", "[", "]")
- [ ] รัน checklist สำนวน (ศิลปะการเขียนด้านบน) แล้ว
- [ ] **อ่านทวนหาคำไทยเพี้ยน/คำหลุดบริบท** — คำวิชาการที่หน้าตาใกล้กันสลับกันได้ง่ายและอ่านผ่าน ๆ ไม่ทันจับ (เคสจริง: "ภาระผูกพันตาม**บรรณานุกรม**" ที่ต้องเป็น "ตาม**บรรทัดฐาน**") พบแล้วแก้ก่อนส่งทุกครั้ง
- [ ] **บรรณานุกรมสะสมขึ้นย่อหน้าใหม่จริงทีละรายการ** ไม่ต่อกันเป็นพืด (ต่อกันแล้วผู้ใช้วางใน Word จะกลายเป็นย่อหน้าเดียว กด Ctrl+T ไม่ได้ผล)
- [ ] **ปีในนาม-ปีทุกจุดยืนยันแล้ว** — ยังไม่ยืนยันต้องเขียน "(ปี — ต้องยืนยัน)" ห้ามใส่ปีที่เดา
