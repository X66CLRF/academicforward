## 🎚️ 0. ด่านบังคับก่อนสร้างไฟล์แรก (SPEC-GATE)

**ห้ามสร้างไฟล์ใด ๆ จนกว่าจะรู้สเปกรูปแบบ** ค่าอย่างขนาดฟอนต์ ระยะบรรทัด และการเยื้อง
ต่างกันไปตามสถาบัน สำนักพิมพ์ และประเภทงาน **ห้ามเดา ห้ามใช้ค่าจากงานก่อนหน้า**

ถามผู้ใช้เป็นคำถามเดียว แล้วแตกเป็น 3 ทาง

| ทาง | เมื่อไหร่ | ทำอะไร |
| :--- | :--- | :--- |
| **ก. มีเอกสารตัวอย่าง** | ผู้ใช้มีไฟล์ที่ผ่านการยอมรับแล้ว | ขอ path แล้ววัดค่าจากไฟล์นั้น (ข้อ 1) — **ทางที่ดีที่สุด** |
| **ข. มีคู่มือรูปแบบ** | สถาบันมีคู่มือเป็นเอกสาร | อ่านคู่มือ แล้วสรุปค่าเป็นตารางให้ผู้ใช้ยืนยัน |
| **ค. ยังไม่มีทั้งสองอย่าง** | งานใหม่เอี่ยม | เสนอค่าตั้งต้นพร้อมบอกชัดว่าเป็นข้อเสนอ รอผู้ใช้ยืนยันทีละข้อ |

ถ้าผู้ใช้ยังไม่ตอบ ให้สร้างไฟล์ด้วยค่าที่เสนอไว้ **พร้อมกำกับในบัตรส่งมอบว่ายังไม่ได้รับการยืนยัน**
ห้ามเงียบแล้วปล่อยให้ผู้ใช้เข้าใจว่าค่านั้นถูกต้องแล้ว

### สิ่งที่ต้องรู้ก่อนสร้าง

```text
[DOC-SPEC]
ภาษาหลักของเอกสาร: [ไทย / อังกฤษ / อื่น ๆ]
ฟอนต์และขนาดเนื้อความ:
ระยะบรรทัด:
ระยะห่างก่อน-หลังย่อหน้า:
การจัดวางย่อหน้าเนื้อความ:
เยื้องบรรทัดแรกของย่อหน้า:
บันไดการเยื้องของหัวข้อแต่ละระดับ:
ขอบกระดาษ บน / ล่าง / ซ้าย / ขวา:
ขนาดและน้ำหนักของหัวบท ชื่อบท หัวข้อแต่ละระดับ:
ตำแหน่งคำบรรยายตาราง / คำบรรยายภาพ:
ที่มาของค่า: [วัดจากไฟล์ / คู่มือสถาบัน / เสนอเอง รอยืนยัน]
```

## 🔍 1. วิธีวัดสเปกจากเอกสารตัวอย่าง (Spec Extraction)

วิธีนี้แม่นที่สุด เพราะได้ค่าที่ **ผ่านการยอมรับของผู้ตรวจมาแล้วจริง** ไม่ใช่การตีความคู่มือ

```python
from docx import Document

d = Document(path)
sec = d.sections[0]
print("ขอบกระดาษ ซม. บน %.2f ล่าง %.2f ซ้าย %.2f ขวา %.2f" % (
    sec.top_margin.cm, sec.bottom_margin.cm, sec.left_margin.cm, sec.right_margin.cm))

for i, p in enumerate(d.paragraphs):
    if not p.text.strip():
        continue
    pf = p.paragraph_format
    r = p.runs[0] if p.runs else None
    print("%3d | สไตล์ %-12s เยื้องบรรทัดแรก %-7s เยื้องซ้าย %-7s ระยะบรรทัด %-5s "
          "จัดวาง %-8s ขนาด %-5s หนา %-5s | %s" % (
        i, p.style.name,
        round(pf.first_line_indent.cm, 2) if pf.first_line_indent is not None else "-",
        round(pf.left_indent.cm, 2) if pf.left_indent is not None else "-",
        pf.line_spacing,
        str(pf.alignment).split(" ")[0] if pf.alignment else "-",
        r.font.size.pt if r and r.font.size else None,
        r.bold if r else None, p.text[:40]))
```

**อ่านผลอย่างไร**

* `ระยะบรรทัด` เป็น `None` แปลว่า **ระยะบรรทัดเดี่ยว** ไม่ใช่ไม่ได้ตั้งค่า
* `จัดวาง` เป็น `-` แปลว่า **ชิดซ้าย** ซึ่งเป็นค่าเริ่มต้น
* ค่าเยื้องของมนุษย์มักไม่ลงตัวเป๊ะ (เช่น 1.52 / 1.96 / 2.54) ให้ยึดตามที่วัดได้จริง อย่าปัดให้สวย
* ดูหลายย่อหน้าของระดับเดียวกัน ถ้าค่าต่างกันเล็กน้อย ให้เลือกค่าที่พบบ่อยที่สุด

**สรุปกลับให้ผู้ใช้ยืนยันเป็นตารางเสมอ** ก่อนเริ่มผลิตไฟล์จริง

## 🚨 2. บั๊กภาษาอักษรเชิงซ้อน — ต้องแก้ทุกไฟล์ ไม่มีข้อยกเว้น

**ใช้กับภาษาไทย ลาว เขมร พม่า อาหรับ ฮีบรู ฮินดี และทุกภาษาที่เป็นอักษรเชิงซ้อน (complex script)**

แม่แบบเปล่าของ `python-docx` ตั้งค่าเริ่มต้นใน `word/styles.xml` เป็น

```xml
<w:lang w:val="en-US" w:eastAsia="en-US" w:bidi="ar-SA"/>
```

`w:bidi` คือช่องภาษาของอักษรเชิงซ้อน ค่าเริ่มต้น `ar-SA` คือภาษาอาหรับ
เอกสารภาษาไทยจึงถูกประมวลผลด้วยกฎภาษาอาหรับ

### อาการที่ผู้ใช้จะเจอ

| อาการ | สาเหตุ |
| :--- | :--- |
| ตัดบรรทัดผิดตำแหน่ง เลขข้อโดดอยู่บรรทัดเดียว ข้อความยาวถูกดันลงบรรทัดใหม่ทั้งก้อน | ไม่ใช้พจนานุกรมตัดคำของภาษานั้น ข้อความที่ไม่มีเว้นวรรคถูกมองเป็นคำเดียวขนาดยักษ์ |
| ขีดเส้นหยักแดงทั้งไฟล์ | ตรวจคำสะกดด้วยพจนานุกรมผิดภาษา |
| ตั้งขนาดฟอนต์แล้วไม่เปลี่ยน | ตั้ง `w:sz` แต่ไม่ได้ตั้ง `w:szCs` ซึ่งเป็นขนาดของอักษรเชิงซ้อน |
| ตั้งตัวหนาแล้วไม่หนา | ตั้ง `w:b` แต่ไม่ได้ตั้ง `w:bCs` |
| จัดกระจายแล้วมีช่องว่างก้อนใหญ่กลางบรรทัด | ใช้การจัดกระจายแบบละติน ไม่ใช่ของภาษานั้น |

> ⚠️ **อาการหลอกที่ทำให้วินิจฉัยผิด** — ถ้าผู้ใช้คัดลอกข้อความไปพิมพ์ใหม่ด้วยแป้นพิมพ์ภาษานั้น
> Word จะติดภาษาให้เอง ปัญหาหายเฉพาะข้อความนั้น ทำให้เข้าใจผิดว่าเป็นปัญหาการพิมพ์
> **ไม่ใช่ปัญหาไฟล์** ห้ามสรุปแบบนั้น ให้เปิด XML ดูเสมอ

### ต้องแก้ 4 จุด ไม่ใช่จุดเดียว

| # | จุด | ค่าที่ต้องตั้ง |
| :---: | :--- | :--- |
| 1 | ค่าเริ่มต้นระดับเอกสาร ใน `styles.xml` | ทุกแท็ก `w:lang` ตั้ง `w:bidi` เป็นรหัสภาษาจริง เช่น `th-TH` |
| 2 | ภาษาของธีมฟอนต์ ใน `settings.xml` | `w:themeFontLang` ตั้ง `w:bidi` เป็นรหัสภาษาจริง |
| 3 | สวิตช์กฎการตัดบรรทัด ใน `settings.xml` | เพิ่ม `<w:applyBreakingRules/>` ใน `<w:compat>` |
| 4 | **ธงอักษรเชิงซ้อนระดับ run** | `<w:cs/>` ใน `w:rPr` ของ **ทุก run** |

> 🔴 **ข้อ 4 สำคัญที่สุดและพลาดกันบ่อยที่สุด** — Word **ไม่สืบทอด** ธง `<w:cs/>` จากสไตล์
> มาใช้ตัดบรรทัด ต้องเขียนลงระดับ run ทุกตัว เอกสารที่พิมพ์บน Word จริงมีธงนี้ครบทุก run
> ตั้งไว้แค่ที่สไตล์**ไม่พอ** อาการจะยังเหมือนเดิมทุกประการ

### การจัดกระจายของภาษาที่ไม่มีช่องว่างระหว่างคำ

การจัดกระจายแบบละติน (`w:jc` = `both`) ยืดเฉพาะช่องว่างระหว่างคำ
ภาษาไทยและภาษาอื่นที่เขียนติดกันไม่มีช่องว่างให้ยืด Word จึงไปดันช่องว่างที่มีอยู่น้อยจุด
ให้กว้างผิดปกติ กลายเป็นช่องโหว่ก้อนใหญ่กลางบรรทัด

Word มีการจัดกระจายสำหรับภาษาไทยโดยเฉพาะ ชื่อ **Thai distributed**
ค่า XML คือ `<w:jc w:val="thaiDistribute"/>` ยืดตามกฎอักษรเชิงซ้อน

**อย่าเหมาว่าห้ามจัดกระจาย** ปัญหาอยู่ที่ *ชนิด* ของการจัดกระจาย ไม่ใช่ตัวการจัดกระจาย
ถ้าสเปกของผู้ใช้ต้องการขอบขวาตรง ให้ใช้ `thaiDistribute` ไม่ใช่ปฏิเสธ

### ⚠️ ลำดับลูกของ `w:rPr` ต้องตรง schema

ถ้าเรียงผิด Word จะถือว่าไฟล์เสียแล้วซ่อมเอง ผลคือค่าที่ตั้งไว้หายไปเงียบ ๆ

```text
rStyle → rFonts → b → bCs → i → iCs → caps → smallCaps → strike → dstrike →
outline → shadow → emboss → imprint → noProof → snapToGrid → vanish → webHidden →
color → spacing → w → kern → position → sz → szCs → highlight → u → effect →
bdr → shd → fitText → vertAlign → rtl → cs → em → lang → eastAsianLayout →
specVanish → oMath
```

**ทุกครั้งที่เพิ่มแท็กลง `w:rPr` ต้องจัดลำดับใหม่** อย่าใช้ `append` แล้วจบ

## 🧬 3. กฎเหล็ก — ห้ามจัดรูปแบบโดยตรง (No Direct Formatting)

**ปัญหาที่เกิดจริง** เมื่อยัดค่าจัดรูปแบบ (ฟอนต์ ขนาด ระยะบรรทัด ระยะห่าง การเยื้อง)
ลงย่อหน้าเป็นราย ๆ ผู้ใช้จะเลือกข้อความทั้งก้อนแล้วกดปุ่มใน Word แก้ทั้งเล่ม**ไม่ได้**
ต้องไล่แก้ทีละย่อหน้าหลายร้อยครั้ง

### กฎ 8 ข้อ

1. **ห้ามใส่การจัดรูปแบบโดยตรงลงย่อหน้าหรือ run เด็ดขาด** ทุกค่าต้องอยู่ใน paragraph style
   ย่อหน้าทำหน้าที่ผูกชื่อสไตล์อย่างเดียว
   ข้อยกเว้นเดียวคือการเน้นเฉพาะจุดในระดับคำ เช่น ตัวหนาของคำเดียวกลางประโยค
2. **ตั้งค่า Normal ให้ครบก่อน** แล้วให้ทุกสไตล์ที่สร้างใหม่ `base_style` เป็น `Normal`
   ผู้ใช้แก้ `Normal` ตัวเดียวต้องเปลี่ยนทั้งเล่ม
3. **ตั้ง `quick_style = True` ทุกสไตล์** ผู้ใช้จะเห็นในแถบสไตล์ของ Word ไม่ต้องเปิดบานหน้าต่าง
4. **ตั้งชื่อสไตล์เป็นภาษาของผู้ใช้ ขึ้นต้นด้วยคำนำหน้าเดียวกัน** เพื่อให้เรียงติดกัน
   ในบานหน้าต่างสไตล์ และแยกออกจากสไตล์ที่ Word ติดมาเอง
   ตัวอย่าง `ต.เนื้อความ` `ต.หัวข้อ` `ต.ชั้น1` — คำนำหน้าจะเป็นอะไรก็ได้ ขอให้สม่ำเสมอ
5. **ฟอนต์ต้องตั้งครบทุกช่อง** `w:rFonts` ต้องมี `ascii` `hAnsi` `cs` `eastAsia`
   และ `w:szCs` คู่กับ `w:sz` เสมอ
6. **ใช้ `keep_with_next` กับหัวข้อและคำบรรยายตาราง** กันหัวข้อค้างท้ายหน้าโดยเนื้อหาไปหน้าถัดไป
   Word จะแสดงสี่เหลี่ยมดำเล็ก ๆ ในขอบซ้าย — **นั่นคือตัวบอกสถานะ ไม่ใช่ข้อความ ไม่พิมพ์ออกมา**
   ควรบอกผู้ใช้ล่วงหน้า ไม่งั้นจะเข้าใจว่าไฟล์เสีย
7. **ก่อนบันทึกทับไฟล์เดิม ต้องดัก `PermissionError`** แล้วแจ้งผู้ใช้ว่าไฟล์เปิดค้างใน Word
   ให้ปิดก่อน **ห้ามเงียบ ห้ามบันทึกเป็นชื่ออื่นแล้วไม่บอก**
8. **ส่งมอบแล้วต้องบอกผู้ใช้ว่ามีสไตล์อะไรบ้าง และแก้ตรงไหนเพื่อเปลี่ยนทั้งเล่ม**

## 📊 4. มาตรฐานตารางและภาพ

### ตาราง — ต้องตั้ง 4 อย่างทุกตาราง

| รายการ | เหตุผล | XML |
| :--- | :--- | :--- |
| หัวตารางซ้ำเมื่อข้ามหน้า | ตารางยาวจะอ่านไม่รู้เรื่องถ้าหัวอยู่หน้าก่อน | `<w:tblHeader/>` ใน `trPr` แถวแรก |
| ปรับพอดีความกว้างหน้ากระดาษ | ตารางแคบลอยกลางหน้าดูไม่เป็นมืออาชีพ | `<w:tblW w:type="pct" w:w="5000"/>` |
| ปรับความกว้างคอลัมน์อัตโนมัติ | คอลัมน์กว้างเท่ากันหมดทำให้ข้อความยาวตกบรรทัดไม่จำเป็น | `<w:tblLayout w:type="autofit"/>` |
| คำบรรยายตั้ง `keep_with_next` | กันคำบรรยายหลุดคนละหน้ากับตาราง | `w:keepNext` |

`w:w="5000"` มีหน่วยเป็นห้าสิบเท่าของเปอร์เซ็นต์ ดังนั้น 5000 คือ 100 เปอร์เซ็นต์

### ตำแหน่งคำบรรยาย

| ประเภท | ตำแหน่ง |
| :--- | :--- |
| **ตาราง** | คำบรรยายอยู่ **เหนือ** ตาราง |
| **ภาพ** | คำบรรยายอยู่ **ใต้** ภาพ |

เป็นหลักของ APA 7th และคู่มือสถาบันส่วนใหญ่ **แต่ต้องยืนยันกับสเปกของผู้ใช้ก่อนเสมอ**
บางสำนักพิมพ์กำหนดต่างออกไป

### ตัวยึดตำแหน่งภาพ

เมื่อยังไม่มีไฟล์ภาพจริง ให้วาง**ตัวยึดตำแหน่งตรงจุดที่เนื้อความพูดถึงภาพนั้นพอดี**
พร้อมบล็อกสเปกที่ผู้ใช้คัดลอกไปสั่งผลิตภาพต่อได้

🚫 **ห้ามเขียนเนื้อหาจบทั้งหัวข้อแล้วค่อยกองตัวยึดตำแหน่งทั้งหมดไว้ท้ายหัวข้อ**
ถ้ากองไว้ท้าย ผู้ใช้และผู้ผลิตภาพไม่รู้ว่าภาพไหนควรไปอยู่ตรงไหน
และตอนจัดเล่มจริงต้องมานั่งเดาตำแหน่งใหม่ทั้งหมด

## 🔢 5. การเยื้องและลำดับข้อ

| กฎ | รายละเอียด |
| :--- | :--- |
| **ห้ามจำลองการเยื้องด้วย space หรือ tab** | วางลง Word แล้วพัง แก้ทีหลังไม่ได้ ต้องใช้คุณสมบัติย่อหน้าเสมอ |
| **แยกให้ออกระหว่างเยื้องบรรทัดแรกกับเยื้องซ้าย** | เยื้องบรรทัดแรก บรรทัดที่สองกลับมาชิดขอบ · เยื้องซ้าย ทั้งย่อหน้าขยับเข้ามาหมด สองอย่างนี้หน้าตาต่างกันมาก ถามผู้ใช้ให้ชัดว่าต้องการแบบไหน |
| **ห้ามใช้บรรทัดว่างแทนการตั้งระยะห่าง** | ยกเว้นสเปกของผู้ใช้ระบุให้ใช้ย่อหน้าว่างจริง ๆ ซึ่งพบได้ในคู่มือสถาบันหลายแห่ง |
| 🚫 **ห้ามซ้อนเลขข้อ** | ถ้าหัวข้อมีเลขของตัวเองอยู่แล้ว เช่น `4.1` `4.2` ห้ามใส่เลขลำดับซ้อนหน้าอีกจนกลายเป็น `1. 4.1` `2. 4.2` ใส่เลขลำดับใหม่ได้เฉพาะรายการที่ยังไม่มีเลขประจำตัว |
| **ห้ามใช้สีเป็นตัวแยกความหมายเพียงอย่างเดียว** | เอกสารวิชาการมักถูกพิมพ์ขาวดำ ให้ใช้ตัวหนา การเยื้อง หรือป้ายกำกับร่วมด้วยเสมอ |

## ✅ 6. ด่านตรวจก่อนส่งมอบ (VERIFY-GATE)

**บังคับรันทุกครั้งก่อนส่งไฟล์ให้ผู้ใช้** ปัญหาทั้งหมดในไฟล์นี้ตรวจด้วยตาไม่เจอ
ต้องเปิด XML ข้างในดู และต้องรายงานผลให้ผู้ใช้เห็นเป็นตารางผ่านหรือไม่ผ่านทีละข้อ

```python
import zipfile, os

def check(path, lang="th-TH"):
    z = zipfile.ZipFile(path)
    d  = z.read("word/document.xml").decode("utf-8")
    st = z.read("word/styles.xml").decode("utf-8")
    se = z.read("word/settings.xml").decode("utf-8")
    ntbl = d.count("<w:tbl>")

    items = [
        ("ธงอักษรเชิงซ้อนครบทุก run",
         d.count("<w:cs/>") == d.count("<w:r>") and d.count("<w:r>") > 0,
         "%d/%d" % (d.count("<w:cs/>"), d.count("<w:r>"))),
        ("ไม่เหลือภาษาเริ่มต้น ar-SA", st.count("ar-SA") == 0, str(st.count("ar-SA"))),
        ("ตั้งภาษาอักษรเชิงซ้อนถูกต้อง", lang in st, lang),
        ("เปิดกฎการตัดบรรทัด", "applyBreakingRules" in se, "-"),
        ("มี szCs คู่กับ sz", st.count("w:szCs") >= st.count("w:sz w:val"), "-"),
        ("หัวตารางซ้ำเมื่อข้ามหน้า",
         ntbl == 0 or d.count("<w:tblHeader/>") >= ntbl,
         "%d/%d" % (d.count("<w:tblHeader/>"), ntbl)),
        ("ตารางพอดีหน้ากระดาษ",
         ntbl == 0 or d.count('w:w="5000"') >= ntbl,
         "%d/%d" % (d.count('w:w="5000"'), ntbl)),
        ("ตารางปรับความกว้างอัตโนมัติ",
         ntbl == 0 or d.count('w:tblLayout w:type="autofit"') >= ntbl,
         "%d/%d" % (d.count('w:tblLayout w:type="autofit"'), ntbl)),
        ("ไม่ซ้อนเลขข้อ",
         not any("%d. %d." % (i, i) in d for i in range(1, 10)), "-"),
        ("ไม่มีการเยื้องด้วย tab หรือ space",
         "<w:t xml:space=\\"preserve\\">    " not in d and d.count("<w:tab/>") == 0, "-"),
    ]
    print("=== %s ===" % os.path.basename(path))
    for name, ok, val in items:
        print("  %-4s %-32s %s" % ("PASS" if ok else "FAIL", name, val))
    return all(ok for _, ok, _ in items)
```

**ถ้าข้อใดไม่ผ่าน ห้ามส่งมอบไฟล์** ให้แก้แล้วตรวจใหม่จนผ่านครบ
ถ้าแก้ไม่ได้จริง ๆ ให้แจ้งผู้ใช้ว่าข้อไหนไม่ผ่านและกระทบอะไร **ห้ามส่งเงียบ ๆ**

> ข้อ "ไม่มีการเยื้องด้วย tab" อาจไม่ใช้กับเอกสารบางประเภทที่ใช้ tab อย่างถูกต้อง
> เช่น สารบัญที่มีจุดไข่ปลานำไปหาเลขหน้า ให้ปรับด่านตรวจตามบริบท แต่ต้องรู้ตัวว่ากำลังยกเว้น

## 🧩 7. ไลบรารีกลาง — ใช้ของที่มีอยู่ ห้ามเขียนใหม่

ทุกอย่างในคู่มือนี้ทำเป็นโค้ดพร้อมใช้แล้วที่ [`Automation/scripts/`](scripts/)

| ไฟล์ | หน้าที่ |
| :--- | :--- |
| `docx_core.py` | ไลบรารีกลาง — `DocBuilder` · สไตล์ · ตาราง · ตัวยึดตำแหน่งภาพ · ธงภาษา · `verify()` · `measure()` |
| `check_docx.py` | ด่านตรวจแบบสั่งจากบรรทัดคำสั่ง ตรวจทีละไฟล์หรือทั้งโฟลเดอร์ |
| `example_report.py` | ตัวอย่างเอกสารครบองค์ประกอบ ก๊อปไปแก้เนื้อหาได้เลย |

```python
from docx_core import DocBuilder, SPEC_TH_ACADEMIC

b = DocBuilder(SPEC_TH_ACADEMIC)
b.p("บทที่ 1", "หัวบท")
b.p("ชื่อบท", "ชื่อบท")
b.body("ย่อหน้าเนื้อความ ปล่อยให้ Word ตัดคำเอง")
b.p("1. ข้อระดับหนึ่ง", "ข้อ1")
b.p("1.1 ข้อระดับสอง", "ข้อ2")
b.table("ตารางที่ 1 ชื่อตาราง", ["ก", "ข"], [(1, 2), (3, 4)])
b.figure_placeholder("1.1", "ชื่อภาพ", "ผังกล่องแนวนอน")
b.save("output.docx")
```

`SPEC_TH_ACADEMIC` คือข้อตกลงการพิมพ์ตั้งต้นสำหรับงานวิชาการไทย
วัดจากเอกสารที่ผ่านการตรวจของสถาบันมาแล้วจริง **ถ้างานใช้ค่าอื่น ให้คัดลอก dict
ไปแก้ อย่าแก้ในไลบรารี** โครงสร้างสเปกอยู่ในหัวไฟล์ `docx_core.py`

```bash
python check_docx.py ไฟล์.docx        # ตรวจไฟล์เดียว
python check_docx.py โฟลเดอร์/         # ตรวจทั้งโฟลเดอร์
python check_docx.py f.docx --lang lo-LA
```

### แยกไฟล์งานของตัวเองแบบนี้

```text
docx_core.py       ไลบรารีกลาง — ไม่ต้องแตะ ใช้ร่วมกันทุกงาน
build_<งาน>.py     เนื้อหาจริงของงานนั้น นำเข้าจาก docx_core
check_docx.py      ด่านตรวจ รันแยกได้ ไม่ผูกกับงานใด
```

**เก็บสคริปต์งานของคุณไว้ที่เดียวกับไฟล์งาน ไม่ใช่ในโฟลเดอร์ชั่วคราว**
ถ้าอยู่ในโฟลเดอร์ชั่วคราวของเซสชัน จะถูกลบทิ้ง แล้วเซสชันถัดไปต้องเขียนใหม่
พร้อมเสี่ยงพลาดซ้ำทุกบั๊กที่แก้ไปแล้ว

🚫 **ห้ามเขียนไลบรารีขึ้นใหม่จากศูนย์** `docx_core.py` แก้บั๊กภาษาไทยไว้ครบแล้ว
เขียนใหม่จะพลาดซ้ำทั้งหมด ถ้าต้องการความสามารถที่ยังไม่มี ให้เพิ่มเข้าไลบรารี ไม่ใช่เขียนแยก

## 🛡️ 9. ข้อห้ามรวม

1. 🚫 **ห้ามเดาสเปกรูปแบบ** ถ้าผู้ใช้ไม่ได้ให้ ให้ถามหรือเสนอพร้อมกำกับว่ารอยืนยัน
2. 🚫 **ห้ามใช้ค่าจากงานก่อนหน้าโดยไม่ถาม** สถาบันและประเภทงานต่างกัน ค่าต่างกัน
3. 🚫 **ห้ามส่งไฟล์ที่ยังไม่ผ่านด่านตรวจ**
4. 🚫 **ห้ามเงียบเมื่อบันทึกไฟล์ไม่สำเร็จ**
5. 🚫 **ห้ามแตะเนื้อหา** ไฟล์นี้รับผิดชอบภาชนะ ไม่ใช่สาระ ถ้าเห็นเนื้อหาผิดให้แจ้ง ไม่ใช่แก้เอง
6. 🚫 **ห้ามสร้างเนื้อหาปลอมมาเติมช่องว่าง** ถ้าผู้ใช้ยังไม่ให้เนื้อหา ให้ใส่ตัวยึดตำแหน่งที่เห็นชัดว่าเป็นตัวยึดตำแหน่ง
