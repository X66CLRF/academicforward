# **🧬 docx-safe-edit-agent — แก้ไฟล์ .docx จำนวนมากโดยฟอร์แมตไม่พัง**

> **สำหรับ**: ทุกงานที่ต้องแก้ข้อความในไฟล์ `.docx` ที่จัดรูปแบบไว้แล้ว — เล่มวิจัย ตำรา คู่มือปฏิบัติงาน เอกสารประเมิน รายงาน แบบฟอร์มราชการ

> **ขอบเขต**: แก้ของที่มีอยู่เป็นหลัก และครอบคลุมการสร้างไฟล์ `.docx` ขึ้นใหม่ด้วย — ถ้าเริ่มจากศูนย์ ห้ามใช้ python-docx แบบตรงไปตรงมา ต้องทำตามหัวข้อ "กฎการสร้างไฟล์ .docx ขึ้นใหม่" ท้ายไฟล์ (บั๊กภาษาไทย + ห้ามจัดรูปแบบโดยตรง)

## **🛑 กฎเหล็ก**

1. **แก้เฉพาะข้อความ ห้ามสร้างย่อหน้าใหม่** วางข้อความใหม่ลง `<w:t>` ตัวแรกของย่อหน้า แล้วล้าง `<w:t>` ที่เหลือให้ว่าง
2. **เพิ่มรายการใหม่ = โคลนย่อหน้าหรือแถวเดิมมาเป็นต้นแบบ** ห้ามประกอบ XML เอง
3. **backup ก่อนเขียนทุกครั้ง** ไม่มีข้อยกเว้น
4. **จำกัดขอบเขตการแทนที่ให้แคบที่สุด** ระบุหัวและท้ายของช่วงเสมอ ห้ามใช้ "ถึงท้ายเอกสาร"
5. **สคริปต์ที่เขียนไฟล์ต้อง dry-run เป็นค่าตั้งต้น** ต้องสั่ง `--write` ถึงเขียนจริง
6. **ของที่เจ้าของพิมพ์เองแล้ว ห้ามทับ** ตรวจก่อนเขียนทุกช่อง

## **⚙️ ทำไมต้องแก้ที่ `<w:t>` เท่านั้น**

ย่อหน้าเดียวใน Word มักมีหลาย run เช่น run แรกเป็น `<w:tab/>` ย่อหน้าแรก run ที่สองเป็นข้อความ run ที่สามเป็นตัวหนา ถ้าประกอบ `<w:p>` ขึ้นใหม่แล้วยัดข้อความทั้งก้อนลงไป จะได้ผลลัพธ์ที่ **tab ย่อหน้าแรกหาย ตัวหนาหาย และบรรทัดตกกลางประโยค**

การเขียนทับเฉพาะเนื้อใน `<w:t>` ทำให้ `<w:p>` `<w:r>` `<w:rPr>` `<w:pPr>` `<w:tab/>` `<w:tcPr>` คงเดิมทุกไบต์ ฟอนต์ ระยะบรรทัด การจัดชิดขอบ กรอบตาราง จึงไม่ขยับ

**ข้อจำกัดที่ยอมรับ**: ย่อหน้าที่มีตัวหนา/ตัวเอียงปนกันกลางประโยค เมื่อแทนข้อความจะเหลือรูปแบบของ run แรกอันเดียว ถ้าต้องคงตัวหนากลางประโยค ให้แยกเป็นสองการแก้ หรือแก้มือ

## **🧰 คำสั่ง**

```python
import docxkit as k

d = k.Doc(path, 'โน้ตว่ากำลังจะแก้อะไร')      # เปิด + snapshot
d.para_replace({'ข้อความเดิม': 'ข้อความใหม่'})  # แทนย่อหน้าตามข้อความเดิม
d.para_map(fn)                                 # ตัดสินใจเองรายย่อหน้า คืน None = ข้าม
d.table_map(idx, fn, ncols=4)                  # แก้เซลล์ในตารางที่ idx
d.table_fill(idx, rows, keep_head=2, proto=2)  # แทนแถวข้อมูลทั้งตาราง
d.save()

k.milestone(path, 'ร่าง02')        # ก๊อบเล่มเต็มเป็นเวอร์ชันใหม่
k.snaps(path)                      # ดู snapshot ทั้งหมด
k.restore(path, 'ชื่อไฟล์.xml')     # กู้กลับ
k.puttext(paragraph_xml, 'ข้อความ') # โคลนย่อหน้าต้นแบบแล้วเปลี่ยนข้อความ

# ตัวหนาเฉพาะบางช่วงในย่อหน้าเดียว
k.puttext_rich(paragraph_xml, [('วลีนำ', True), (' เนื้อความที่เหลือ', False)])
```

### ตัวหนาเฉพาะบางช่วง

`puttext` วางข้อความทั้งก้อนลง run เดียว ทั้งย่อหน้าจึงเป็นรูปแบบเดียว ถ้าต้องการ **วลีนำตัวหนา + เนื้อความตัวปกติ** ในย่อหน้าเดียว ให้ใช้ `puttext_rich` ซึ่งโคลน run ต้นแบบหลายชุดแล้วเติมหรือถอด `<w:b/>` รายชุด

**ต้องใส่ `<w:bCs/>` คู่กับ `<w:b/>` เสมอ** ไม่งั้นตัวหนาไม่ติดกับข้อความภาษาไทยและภาษาอื่นที่เป็น complex script — เป็นกับดักเดียวกับ `w:sz` / `w:szCs` และ `w:rFonts` ที่ต้องตั้ง `cs` ด้วย

**จุดตัดวลีนำในภาษาไทยมักเป็นช่องว่างแรกของย่อหน้า** เพราะภาษาไทยไม่เว้นวรรคในวลี เช่น `กรณีสื่อโสตทัศน์ที่วัสดุเสื่อมสภาพ` แล้วเว้นวรรคก่อนขึ้นประโยค ใช้กฎนี้แบ่งได้ตรงเกือบทุกครั้ง แต่ควรกันไว้ว่าถ้าวลีนำยาวผิดปกติ (เกิน ~๖๐ ตัวอักษร) ให้ข้าม เพราะแปลว่าย่อหน้านั้นไม่มีวลีนำจริง

## **⚠️ กับดักที่ทำพังมาแล้ว**

| กับดัก | อาการ | วิธีกัน |
| :--- | :--- | :--- |
| ขอบเขต "ถึงท้ายเอกสาร" | ลบท้ายเล่มหายพันกว่าย่อหน้าในคำสั่งเดียว | ระบุหัวและท้ายของช่วงเสมอ หรือทำงานในขอบเขตตารางเดียว |
| regex `<w:t[^>]*>` | ไปจับ `<w:tab .../>` ได้ข้อความปนโค้ด | ใช้ `<w:t(?:\s[^>]*)?>` |
| regex `<w:p.*?</w:p>` | ไปจับ `<w:pPr>` ลำดับย่อหน้าเพี้ยนทั้งไฟล์ | ต้องมี `\b` เสมอ: `<w:p\b.*?</w:p>` |
| ต้นแบบเป็นย่อหน้าว่าง | ไม่มี `<w:t>` ให้วางข้อความ ผลลัพธ์ออกมาว่างทั้งชุด | เลือกต้นแบบที่มี `<w:t>` จริงเท่านั้น |
| ลืม escape | `&` `<` `>` ทำให้ Word เปิดไฟล์ไม่ขึ้น | ใช้ `puttext` ที่ escape ให้แล้ว |
| ไฟล์เปิดค้างใน Word | `PermissionError` ตอนเขียน | ปิด Word ก่อน แต่ยังอ่าน snapshot ล่าสุดเพื่อวิเคราะห์ต่อได้ |

**โน้ตทำงานต้องไม่หลุดลงเล่ม** ร่างที่เอเจนต์เขียนไว้มักมีบรรทัดคุยกับเจ้าของปนอยู่ (`*⚠ …*` `*หลักฐาน: …*` `> หมายเหตุ`) ตัวกรองต้องดักทั้งกรณีที่สัญลักษณ์อยู่หน้าสุดและกรณีที่มีตัวหนา `*` นำหน้าก่อน — ตรวจซ้ำหลังเขียนเสมอด้วยการไล่หาย่อหน้าที่ขึ้นต้นด้วย `*` หรือมี `⚠` แล้ว**ลบทั้งย่อหน้า ไม่ใช่ลบแค่สัญลักษณ์** และรายงานข้อความที่ลบกลับให้เจ้าของ เพราะเป็นรายการหลักฐานที่ยังขาด (`clean_notes.py`)

**เส้นหยักแดงใต้ข้อความที่เพิ่งแก้ ไม่ใช่ความผิดพลาด** เป็นการตรวจสะกดของ Word บน run ใหม่ ไม่เกี่ยวกับฟอร์แมตและไม่ติดตอนพิมพ์ ห้ามแก้ XML เพื่อลบเส้นแดง ถ้ารำคาญให้ผู้ใช้สั่ง Review → Language → Set Proofing Language → Do not check spelling or grammar

## **🖼️ แทนรูปโดยคงเฟรมและสัดส่วนของเทมเพลท**

ขนาดที่แสดงของรูปอยู่ใน `<wp:extent cx cy>` (๙๑๔๔๐๐ EMU = ๑ นิ้ว) และการครอบตัดอยู่ใน `<a:srcRect>` **ทั้งคู่อยู่ใน `document.xml` ไม่ใช่ในไฟล์ภาพ**

ดังนั้น **สลับเฉพาะไบต์ของไฟล์ใน `word/media/imageN.xxx` โดยไม่แตะ XML** = รูปใหม่ไหลเข้าเฟรมเดิมทันที เทียบเท่าการคลิกขวาแล้วสั่งเปลี่ยนรูปภาพใน Word และปลอดภัยที่สุดเพราะ XML ไม่ถูกแก้เลย

**จัดการเรื่องรูปยืดที่ตัวไฟล์ก่อนสลับ** ด้วย Pillow

| โหมด | ทำอะไร | ใช้กับ |
| :--- | :--- | :--- |
| **cover** | ขยายเต็มเฟรมแล้วครอบส่วนเกิน ไม่ยืด ขอบโดนตัด | ภาพถ่าย ภาพกิจกรรม ภาพหน้าจอ |
| **contain** | ใส่ทั้งภาพ เติมพื้นขาวข้าง ไม่ยืด ไม่ตัด | เอกสาร ใบประกาศ คำสั่ง แผนภูมิ ตาราง |
| stretch | ยืดเต็มเฟรม สัดส่วนเพี้ยน | ไม่ใช้ |

**เลือกโหมดตามชนิดของภาพ อย่าใช้โหมดเดียวทั้งเล่ม** เอกสารที่โดน cover จะถูกตัดหัวกระดาษหรือลายเซ็นทิ้ง

**ก่อนแทนต้องทำบัญชีสล็อตก่อน** (`Evaluation/scripts/slots.py`) ออกไฟล์ TSV ที่มี จำนวนรูปต่อบล็อก · ขนาดเฟรมรายรูปเป็นนิ้ว · แนวนอน/แนวตั้ง · จุดครอบตัด · ชื่อไฟล์ media · คำบรรยายเดิม แล้วจับคู่ด้วย **จำนวนรูป + แนวรูป + สัดส่วน พร้อมกัน** เพราะบล็อก ๓ รูปมีทั้งแบบ "นอนกว้างบน + ตั้งคู่ล่าง" และ "ตั้งสูงสามใบเรียง" ซึ่งใช้แทนกันไม่ได้

## **📄 ยืมเล่มของคนอื่นมาเป็นเทมเพลท**

1. ก๊อบเป็นไฟล์ใหม่ก่อนเสมอ ห้ามแก้เล่มเจ้าของเทมเพลท
2. สร้างเล่มใหม่จากเทมเพลททุกครั้งที่รันสคริปต์รอบใหญ่ อย่า patch ทับเล่มที่แก้พลาด
3. **จำนวนรายการมาจากข้อมูลจริงของเจ้าของเล่มใหม่ ไม่ใช่จำนวนช่องในเทมเพลท** ถ้าไม่เท่ากันต้องทักผู้ใช้ก่อน พร้อมบอกว่ามากกว่าหรือน้อยกว่าเท่าไร
4. ตรวจความสอดคล้องข้ามส่วน รายการเดียวกันที่ปรากฏหลายที่ในเล่มต้องนับได้เท่ากัน
5. ไล่ล้างร่องรอยเจ้าของเดิมให้ครบ ชื่อ ตำแหน่ง หน่วยงาน ชื่อผู้ลงนาม ข้อมูลเฉพาะตัว และรูปในภาคผนวก
6. **ชื่อเจ้าของเทมเพลทบางจุดต้องคงไว้** เช่น รายชื่อเพื่อนร่วมงานในผังโครงสร้างองค์กร ตรวจก่อนลบทุกครั้ง

**แยกไฟล์ทำงาน** ส่วนที่หนักและแก้บ่อย เช่น ภาคผนวกรูป ให้ตัดออกมาเป็นไฟล์ต่างหาก (`Evaluation/scripts/split_appendix.py`) เปิดเร็วขึ้นมาก ตรวจง่าย แก้พังก็ไม่กระทบเนื้อเล่ม **ต้องคง `<w:sectPr>` ท้าย body ไว้** ไม่งั้นขนาดหน้า ขอบกระดาษ และ header หาย ตอนรวมกลับต้องรีแมป `rId` และชื่อ `media/imageN` ไม่ให้ชนกัน

## **🆕 กฎการสร้างไฟล์ .docx ขึ้นใหม่ (ไม่ใช่แก้ไฟล์เดิม)**

### ส่วนที่ ๑ — 🔴 บั๊กภาษาอักษรเชิงซ้อนของ python-docx (ต้องแก้ทุกไฟล์ ไม่มีข้อยกเว้น)

**อาการที่ผู้ใช้เจอ**

1. Word **ตัดบรรทัดภาษาไทยผิดตำแหน่ง** ข้อความไทยยาวที่ไม่มีเว้นวรรคถูกดันลงบรรทัดใหม่ทั้งก้อน ทำให้เลขข้อโดดอยู่บรรทัดเดียว
2. ตัวตรวจคำสะกด**ขีดเส้นหยักแดงทั้งไฟล์**
3. เมื่อจัดกระจายแบบไทย ผลลัพธ์ผิดเพี้ยน

**สาเหตุ** แม่แบบเปล่าของ `python-docx` ตั้งค่าเริ่มต้นใน `word/styles.xml` เป็น

```xml
<w:lang w:val="en-US" w:eastAsia="en-US" w:bidi="ar-SA"/>
```

ค่า `ar-SA` คือ**ภาษาอาหรับ** Word จึงประมวลผลข้อความไทยด้วยกฎภาษาอาหรับ ไม่ใช้พจนานุกรมตัดคำไทย และตรวจคำสะกดด้วยพจนานุกรมที่ไม่ตรง เอกสารที่พิมพ์บน Word จริงใช้ `w:bidi="th-TH"`

🚨 **อาการหลอก** ถ้าผู้ใช้ก๊อปข้อความไปพิมพ์ใหม่บนแป้นไทย Word จะติดภาษาไทยให้เอง ปัญหาหายเฉพาะข้อความนั้น ทำให้เข้าใจผิดว่าเป็นปัญหาการพิมพ์ ไม่ใช่ปัญหาไฟล์

**วิธีแก้ที่ต้องทำทุกครั้ง ก่อนบันทึกไฟล์**

1. ไล่ทุกแท็ก `w:lang` ใน `doc.styles.element` แล้วตั้ง `w:bidi` เป็น `th-TH`
2. ใน `doc.settings.element` หาแท็ก `w:themeFontLang` แล้วตั้ง `w:bidi` เป็น `th-TH` ถ้าไม่มีแท็กนี้ให้สร้างขึ้นมาใหม่
3. ทุกสไตล์ที่สร้างเองต้องมี `w:lang` พร้อม `w:bidi` เป็น `th-TH` ใน `rPr` ของสไตล์
4. **ตรวจก่อนส่งมอบทุกครั้ง** เปิด `word/styles.xml` แล้วยืนยันว่าไม่เหลือ `ar-SA`

```python
from docx.oxml.ns import qn
from docx.oxml import OxmlElement

def set_thai_lang(doc):
    """แก้บั๊ก ar-SA — ต้องเรียกทุกครั้งหลังสร้าง Document()"""
    for lang in doc.styles.element.findall('.//' + qn('w:lang')):
        lang.set(qn('w:bidi'), 'th-TH')
    st = doc.settings.element
    tfl = st.find(qn('w:themeFontLang'))
    if tfl is None:
        tfl = OxmlElement('w:themeFontLang')
        tfl.set(qn('w:val'), 'en-US')
        st.append(tfl)
    tfl.set(qn('w:bidi'), 'th-TH')
```

### ส่วนที่ ๒ — ห้ามจัดรูปแบบโดยตรง

**เคสจริงที่พัง** เอเจนต์สร้างไฟล์ด้วย python-docx แล้วยัดค่าจัดรูปแบบลงย่อหน้าเป็นราย ๆ (direct formatting) ผลคือผู้ใช้เลือกทั้งก้อนแล้วกดปุ่มระยะบรรทัดใน Word **แก้ทั้งเล่มไม่ได้** เพราะค่าที่ติดอยู่รายย่อหน้าชนะค่าสไตล์เสมอ ต้องไล่แก้ทีละย่อหน้าทั้งเล่ม

1. **ห้ามใส่การจัดรูปแบบโดยตรงลงย่อหน้าหรือ run เด็ดขาด** ทุกค่า (ฟอนต์ ขนาด ระยะบรรทัด การเยื้อง การจัดแนว) ต้องอยู่ใน **paragraph style** เท่านั้น ย่อหน้าทำหน้าที่**ผูกชื่อสไตล์อย่างเดียว**
2. **ตั้งค่า `Normal` ให้ครบก่อน** แล้วให้ทุกสไตล์ที่สร้างใหม่ `base_style` เป็น `Normal` — ผู้ใช้แก้ `Normal` ตัวเดียวต้องเปลี่ยนทั้งเล่ม
3. **ตั้ง `quick_style = True` ทุกสไตล์** ผู้ใช้จะเห็นในแถบสไตล์ของ Word ไม่ต้องไปงมในบานหน้าต่างสไตล์
4. **ตั้งชื่อสไตล์เป็นภาษาไทย ขึ้นต้นด้วยคำนำหน้าเดียวกัน** เพื่อให้เรียงติดกันในบานหน้าต่างสไตล์ เช่น `ต.เนื้อความ` `ต.หัวข้อ` `ต.ชั้น1`
5. **ฟอนต์ต้องเซ็ตช่อง complex script ด้วย ไม่ใช่แค่ `ascii` และ `hAnsi`** — ต้องตั้ง `w:rFonts` ครบทั้ง `ascii` `hAnsi` `cs` `eastAsia` และตั้ง `w:szCs` คู่กับ `w:sz` ถ้าตัวหนาหรือตัวเอียงต้องเพิ่ม `w:bCs` และ `w:iCs` **ไม่ทำข้อนี้ ภาษาไทยจะไม่เปลี่ยนฟอนต์และขนาดตามที่สั่ง**
6. **ค่าจัดรูปแบบให้ยึดตาม** [`../Writing/nsru-2568-manual-reference.md`](../Writing/nsru-2568-manual-reference.md) หัวข้อ **"สเปกการจัดรูปแบบเนื้อหาในไฟล์ Word"** ห้ามตั้งค่าเอาเองจากความจำ
7. **ก่อนบันทึกทับไฟล์เดิม ต้องดัก `PermissionError`** แล้วแจ้งผู้ใช้ว่าไฟล์เปิดค้างอยู่ใน Word ให้ปิดก่อน **ห้ามเงียบ ห้ามข้ามไปเฉย ๆ**
8. **ส่งมอบแล้วต้องบอกผู้ใช้ว่ามีสไตล์อะไรบ้าง และแก้ตรงไหนเพื่อเปลี่ยนทั้งเล่ม** เช่น "ระยะบรรทัดทั้งเล่มอยู่ที่สไตล์ `Normal` แก้ที่เดียวเปลี่ยนหมด"
