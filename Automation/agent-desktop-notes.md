# บันทึกเรียนรู้: agent-desktop (ให้ AI ใช้โปรแกรมบนเดสก์ท็อปผ่าน accessibility tree)

> สถานะ: **บันทึกความรู้ ยังไม่ได้ติดตั้ง/ลองใช้** · อ่านจาก repo จริง `github.com/vercel-labs/agent-desktop` (commit 2026-10-31) เมื่อ 2026-11-02
> ที่มา: เจ้าของส่งลิงก์มาให้ศึกษา "ไหน ๆ ทำเกี่ยวกับสกิล" — ข้อ 1–3 คือตัวเครื่องมือ ข้อ 4 คือวิธีเขียนสกิลที่เราควรยืมมาใช้

## 1. คืออะไร

CLI ของ Vercel Labs (Apache-2.0, เขียนด้วย Rust, ลงผ่าน `npm install -g agent-desktop`) ให้ agent **อ่านและกดโปรแกรมบนเครื่อง**
ผ่าน accessibility tree ของระบบปฏิบัติการ (Windows = UI Automation) — ไม่ใช่จับภาพหน้าจอแล้วเดาตำแหน่งพิกเซล

```
agent-desktop snapshot --app <โปรแกรม> -i      # ได้ JSON ทุกปุ่ม/ช่องที่กดได้ แต่ละตัวมี ref เช่น @s8f3k2p9:e8
agent-desktop click '@s8f3k2p9:e8'             # กดตาม ref (PowerShell ต้องใส่ '...' ไม่งั้น @ เป็น splatting)
agent-desktop snapshot --app <โปรแกรม> -i      # อ่านใหม่เพื่อยืนยันว่าเปลี่ยนจริง
```

| เทียบกับ | ต่างกันยังไง |
|---|---|
| computer use (จับภาพหน้าจอ) | agent-desktop อ่านเป็นข้อความ JSON → ถูกกว่า (token น้อย) แม่นกว่า ไม่ขึ้นกับความละเอียดจอ/ธีม · แต่โปรแกรมที่วาด UI เอง (ไม่เปิด accessibility) จะอ่านไม่เห็น |
| Claude in Chrome / Playwright | ใช้กับเว็บ · agent-desktop ใช้กับโปรแกรมเดสก์ท็อป |
| สคริปต์/API ของโปรแกรมเอง | ถ้าโปรแกรมมี API/CLI ใช้อันนั้นก่อนเสมอ agent-desktop คือทางสุดท้ายสำหรับโปรแกรมที่มีแต่หน้าจอ |

## 2. จุดเด่นด้านความปลอดภัย (ควรเข้าใจก่อนใช้)

- **headless เป็นค่าเริ่มต้น:** กดผ่าน accessibility API ไม่ขยับเมาส์ ไม่แย่งโฟกัส — ผู้ใช้ทำงานอื่นต่อได้
  การขยับเมาส์/พิมพ์จริงต้องใส่ `--headed` และสกิลเขาห้ามสลับไป `--headed` เองเพื่อแก้ตอนพัง ต้องให้คนอนุญาตก่อน
- **ref ใช้ได้ครั้งเดียวต่อ snapshot:** UI เปลี่ยน → `STALE_REF` ต้องอ่านใหม่ ไม่มีการกดผิดปุ่มเพราะหน้าจอเลื่อน
- **ผลทุกคำสั่งบอกว่า "กดซ้ำได้ไหม"** (`disposition.retry: safe` เฉพาะเมื่อแน่ใจว่ายังไม่ได้กด) — กันกดยืนยัน/ส่งฟอร์มซ้ำ
- **ปุ่มลัดอันตรายถูกบล็อก** (`alt+f4`, `win+l`, `win+r`, `ctrl+shift+esc` …) ต้อง `--force`
- **ข้อมูลส่วนตัว:** snapshot / ภาพหน้าจอ / clipboard มีข้อมูลบนจอทั้งหมด ห้ามแนบลง log หรือ repo สาธารณะ
  (หน้าจอระบบห้องสมุดมีข้อมูลผู้ใช้บริการ — เข้าข่าย PDPA)

## 3. บน Windows (เครื่องเจ้าของ)

- Windows 10 1809+ · ไม่ต้องขอสิทธิ์ แต่กดโปรแกรมที่รันแบบ Administrator ไม่ได้ถ้า terminal ไม่ได้เป็น admin
- ใช้ไม่ได้: หน้าจอ UAC, หน้าล็อกอิน, เครื่องที่ล็อกจอ, scheduled task ที่รันเป็น SYSTEM → **ทำงานกลางคืนตอนล็อกจอไม่ได้**
- หน้าต่างย่อ (minimize) อยู่กดไม่ได้ ต้อง `restore` ก่อน · แอป Electron/Chromium (เช่น Canva desktop) ต้องรอให้โหลดเสร็จ (`--timeout-ms` ยาวขึ้น)
- `type` (พิมพ์ทีละตัว) ต้อง `--headed` · ใส่ข้อความแบบ headless ใช้ `set-value`

**งานของเราที่อาจใช้ได้ (ยังไม่ได้ลอง ต้องเช็กว่าโปรแกรมเปิด accessibility tree ให้อ่านไหม):**
- โปรแกรมเดสก์ท็อปที่ไม่มี API — หน้าจอระบบงานที่ต้องกรอกซ้ำ ๆ
- ตั้งค่า Windows ในห้องแล็บที่ไม่มีคำสั่ง (`lab-setup`) — **ต้องระวังเป็นพิเศษ** repo นั้นทำลายข้อมูลได้ ห้ามรันเองถ้าเจ้าของไม่สั่ง
- Premiere Pro: UI วาดเองเป็นส่วนใหญ่ น่าจะอ่านได้น้อย — งานตัดต่อใช้ `premierekit` (XML) ต่อไป

## 4. วิธีเขียนสกิลที่ควรยืมมาใช้กับสกิลของเรา

1. **SKILL.md หลักสั้น (80 บรรทัด) + ตาราง "เปิดไฟล์ไหนเมื่อไร"** — ส่วนอ้างอิงอยู่ใน `references/` โหลดเฉพาะตอนต้องใช้
   ตรงกับกฎ "คู่มือยาว = ดัชนี + โฟลเดอร์ส่วน" ของเรา (AGENTS.md) แต่ของเขาเขียนเงื่อนไขเป็น "Open it when …" ชัดกว่า "อ่านทุกครั้ง"
2. **ตัวเครื่องมือพกคู่มือของตัวเอง ตรงรุ่น** (`agent-desktop skills get desktop`) — คู่มือกับโค้ดไม่มีทางเพี้ยนกันข้ามเวอร์ชัน
   ใช้กับ `desk-utils` ได้: ให้ `py -m motionkit --help` / `py -m photo_post --help` ชี้ SKILL.md ของตัวเอง
3. **ทุกคำสั่งตอบ JSON รูปเดียว** `{ok, data | error:{code, disposition, suggestion}}` — agent ตัดสินใจจาก `code` ไม่ใช่จากข้อความ
   (เขาเขียนกำกับว่า "ข้อความเปลี่ยนได้ ให้แยกกรณีด้วย code") · สคริปต์ของเราส่วนใหญ่พิมพ์ข้อความไทยให้คนอ่าน agent ต้องเดาความหมาย
4. **บอกชัดว่าอะไร "ห้ามทำเพื่อแก้ปัญหา"** เช่น ห้ามสลับ headed เพื่อกู้ความล้มเหลว ห้ามกดซ้ำถ้า retry ไม่ใช่ safe — กฎแบบ "ห้าม + เหตุผล" ทำให้ agent ไม่หาทางลัดเอง
5. **ไฟล์สกิลแยกตามแพลตฟอร์ม** (`agent-desktop-windows`, `-macos`, `-linux`) โหลดเฉพาะของเครื่องที่รันอยู่ — แบบเดียวกับที่เราควรแยกส่วน Windows/PowerShell ออกจากส่วนทั่วไป
6. **`docs/solutions/` เก็บบทเรียนจากบั๊ก** แยกจากคู่มือ — เทียบได้กับหัวข้อ "ประวัติ" ในสกิลของเรา (ของเราดีกว่าตรงที่อยู่ไฟล์เดียวกับกฎ agent เห็นแน่)

## 5. งานค้าง

1. เลือกงานจริง 1 งานที่ต้องกดโปรแกรมเดสก์ท็อปซ้ำ ๆ (เจ้าของบอก) → ลง `npm install -g agent-desktop` บนเครื่องเจ้าของ →
   `agent-desktop snapshot --app <โปรแกรม> -i` ดูว่าโปรแกรมนั้นอ่านได้ไหมก่อนลงแรง
2. ข้อ 4.2–4.3 ทดลองกับ `desk-utils/tools/motionkit` ก่อน (เครื่องมือใหม่ แก้ง่าย) ถ้าดีค่อยขยายไปตัวอื่น
