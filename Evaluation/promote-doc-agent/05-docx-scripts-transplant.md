## **🐍 สคริปต์ช่วยแก้ไฟล์ .docx**

อยู่ใน `Evaluation/scripts/` ใช้เมื่อมีไฟล์เล่มอยู่แล้วและต้องเขียนเลขอ้างลงไป

สคริปต์ที่แก้เล่ม (`bold_lead` `cite` `clean_notes` `org` `slots` `split_appendix`) อ่าน path เล่มจากตัวแปร `PROMOTE_DOCX` — ตั้งก่อนรันทุกครั้ง เช่น PowerShell `$env:PROMOTE_DOCX = "<path เล่ม .docx>"`

```bash
pip install python-docx        # จำเป็น
pip install pymupdf            # เฉพาะงานอ่านเลขหน้าจาก PDF

cd Evaluation/scripts

python audit.py "<path.docx>"                        # ดูสถานะ ไม่เขียนอะไร
python propose.py "<path.docx>" > sheet.tsv          # ออกใบตรวจ
# เติมคอลัมน์ cite เฉพาะแถว EMPTY แล้วให้ผู้ใช้ตรวจ
python apply.py "<path.docx>" sheet.tsv --dry-run    # ลองก่อน
python apply.py "<path.docx>" sheet.tsv              # เขียนจริง
python renumber.py "<path.docx>" --dry-run           # ตอนแทรกหรือลบเอกสารแนบ
```

`propose.py` ทำเครื่องหมายให้ทุกแถว

| state | ความหมาย |
| :--- | :--- |
| `DONE` | ผู้ใช้เขียนเองแล้ว **ห้ามแตะ** |
| `EMPTY` | ยังว่าง เติมตรงนี้ |
| `HEAD` | แถวหัวตาราง ข้ามไป |

คอลัมน์ `prefix` สคริปต์เดาให้จากแถวพี่น้องในตารางเดียวกัน **ที่เดามาต้องให้ผู้ใช้ตรวจ** เพราะแถวที่คอลัมน์ ๑ ว่างเพราะ merge cell อาจยืมหัวข้อผิดหมวด

### ข้อจำกัดที่ต้องรู้

- เล่มแบบนี้มักใช้ Word style `Normal` ล้วน จับด้วย style ไม่ได้ ต้องจับด้วย pattern ข้อความ
- ในช่องคอลัมน์ ๓ มีทั้งตัวปกติและตัวหนาปนกัน **ห้ามเขียนทับทั้งช่อง** ตัวหนาจะหาย ให้ต่อข้อความท้ายช่องแทน
- ย่อหน้าคำบรรยายที่ฟอร์แมตปนกันในย่อหน้าเดียว สคริปต์จะข้ามและรายงาน อย่าฝืนแก้
- **ห้ามยุ่งกับเลขไทย/เลขอารบิก** ผู้ใช้มี VBA แปลงทั้งเล่มทีเดียว
- **ห้ามยุ่งกับ header/footer เลขหน้า สารบัญ** ผู้ใช้พิมพ์เอง

## **🧬 งานคัดลอกเล่มจากเทมเพลทของคนอื่น (Template Transplant)**

กรณีที่พบบ่อย: ผู้ใช้มีเล่มของเพื่อนร่วมงานที่ทำเสร็จแล้ว และต้องการ "ก๊อบแล้วแทนที่" เป็นของตัวเอง วิธีนี้ทำได้และเร็วกว่าเริ่มจากฟอร์มเปล่ามาก แต่มีกับดักที่ต้องกันไว้ก่อน

### กฎการแทนที่

1. **ก๊อบไฟล์ต้นฉบับเป็นเล่มใหม่ก่อนเสมอ ห้ามแก้เล่มเจ้าของเทมเพลท** ตั้งชื่อเล่มใหม่ให้มีชื่อผู้ขอรับการประเมินและเลขร่าง เช่น `สมรรถนะ [2569] - <ชื่อ> - ระดับชำนาญการ - ร่าง01.docx`
2. **สร้างเล่มใหม่จากเทมเพลททุกครั้งที่รันสคริปต์รอบใหญ่** อย่า patch ทับเล่มที่แก้พลาด ความเสียหายจะสะสม
3. **จำนวนรายการต้องมาจาก JD ของผู้ขอรับการประเมิน ไม่ใช่จำนวนช่องในเทมเพลท** เลข ๑๓ ข้อของเจ้าของเทมเพลทไม่ใช่เกณฑ์ ถ้า JD มี ๑๕ ข้อก็ต้องเป็น ๑๕ และถ้ามี ๘ ข้อก็เป็น ๘ — **ทักผู้ใช้ทุกครั้งที่จำนวนไม่เท่ากัน** พร้อมบอกว่ามากกว่าหรือน้อยกว่าเท่าไร
4. **ตรวจความสอดคล้องข้ามส่วน** รายการงานในส่วนที่ ๑ (การปฏิบัติงานมีดังนี้) กับส่วนที่ ๒ (ลักษณะงานที่ปฏิบัติ) ต้องนับได้เท่ากันและเรียงตรงกัน ถ้าที่หนึ่งยุบข้อ อีกที่ต้องยุบด้วย
5. **ส่วนที่ ๓ ไม่ใช่เรื่องจำนวน** ตารางสมรรถนะ ๑๔ หมวด (ความรู้ ๒ · ทักษะ ๔ · สมรรถนะหลัก ๓ · สมรรถนะเฉพาะ ๕) เป็นฟอร์มตายตัวเท่ากันทุกคน ต่างกันแค่เนื้อความในคอลัมน์ ๓
6. **ของที่ยังไม่มีข้อมูล ให้ใส่ความเรียงไปก่อน เว้นตัวเลขและเลขหลักฐานไว้** อย่าหยุดรอข้อมูลจนงานค้าง ระบุจุดที่เว้นไว้ให้ผู้ใช้เห็นเป็นรายการ
7. **ข้อมูลส่วนตัวห้ามเดาเด็ดขาด** วันเกิด วันบรรจุ เลขที่ตำแหน่ง อัตราเงินเดือน อายุราชการ ประวัติการดำรงตำแหน่ง — ถ้าผู้ใช้ยังไม่ให้ ให้ข้ามและแจ้ง
