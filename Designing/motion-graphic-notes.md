## 1. หลักคิด: LLM ไม่ได้ "เจนวิดีโอ" แต่เขียนโค้ดที่วาดภาพตามเวลา

| ชนิด AI | ทำงานยังไง | ข้อดี / ข้อเสีย |
|---|---|---|
| Video model (Veo, Kling, Seedance ฯลฯ) | วาดพิกเซลทีละเฟรมโดยตรง | ภาพเหมือนถ่ายจริง · แพง หน้าตัวละครเพี้ยนข้ามฉาก แก้จุดเดียวต้องเจนใหม่ทั้งคลิป |
| LLM (Claude, GPT, Gemini) | เขียน HTML/CSS/SVG/Canvas/JS ที่บอกว่า "วินาทีไหนอะไรอยู่ตรงไหน" แล้วให้เครื่อง render เป็น MP4 | ถูก แม่น แก้ได้ทีละจุด ตัวละครหน้าเดิมทุกฉาก · ได้แค่สไตล์กราฟิก/การ์ตูน ไม่ใช่ภาพถ่าย |

- บทบาทของ agent = **ผู้กำกับ + คนเขียนบท + แอนิเมเตอร์** ไม่ใช่กล้อง
- เทียบง่าย ๆ: เหมือนตั้ง animation ใน PowerPoint ว่าอะไรเข้าก่อน-หลัง แต่ละเอียดถึงระดับเฟรม
- เหมาะกับงานเรา: สื่อแนะนำบริการ/สอนใช้ระบบ/สรุปความรู้ — ต้องการ "อ่านรู้เรื่อง แก้ง่าย" มากกว่า "สมจริง"

## 2. สายการผลิต (pipeline)

```
บท (ภาษาไทย) → ตัดเป็นฉาก + จังหวะเวลา → เสียงพากย์ (TTS) → วัดความยาวเสียงจริง
→ เขียนฉากเป็นโค้ด (HTML/SVG) ผูกกับเวลา → พรีวิวในเบราว์เซอร์ → render เป็นเฟรม → ffmpeg รวมภาพ+เสียง → MP4
```

ลำดับสำคัญ: **ทำเสียงก่อนแล้วค่อยวางภาพ** — ความยาวฉากต้องมาจากความยาวเสียงพากย์จริง ไม่ใช่เดา
ไม่งั้นตัวหนังสือขึ้นก่อน/หลังเสียง

### 2.1 สเปกฉาก (ให้ agent เขียนก่อนเขียนโค้ด)

ตัวอย่างลำดับเหตุการณ์จากโพสต์ (สไตล์สติ๊กแมนสเก็ตช์):

| เวลา | เหตุการณ์ |
|---|---|
| 0:00–0:02 | สติ๊กแมนเดินเข้าจากซ้าย |
| 0:02–0:04 | เครื่องหมายตกใจเด้งขึ้นเหนือหัว |
| 0:04–0:07 | กล้องซูมเข้า ตัวหนังสือสรุปประเด็นปรากฏ |
| 0:07 | ตัดไปฉากถัดไป |

ให้เก็บเป็นข้อมูล (JSON) ไม่ใช่แค่ข้อความ — แก้คำพูด/เวลาแล้ว render ใหม่ได้โดยไม่แตะโค้ดฉาก:

```json
{ "fps": 30, "size": [1920, 1080],
  "scenes": [
    { "id": "s1", "voice": "s1.wav", "start": 0.0,
      "events": [
        { "t": [0, 2], "do": "walk-in", "who": "stick", "from": "left" },
        { "t": [2, 4], "do": "pop", "what": "exclaim", "anchor": "stick.head" },
        { "t": [4, 7], "do": "zoom", "to": 1.4 },
        { "t": [4.3, 7], "do": "text", "say": "สรุปประเด็นภาษาไทย" } ] } ] }
```

### 2.2 เทคนิคในสไตล์สติ๊กแมน (จากโพสต์)

- ตัวละครเป็น SVG เส้นหนาเหมือนวาดมือ **แยกชิ้น** หัว ลำตัว แขน ขา → หมุนแต่ละชิ้นรอบข้อต่อ (`transform-origin` ที่ไหล่/สะโพก) ได้ท่ายกแขน ก้าวขา หันหัว
- เส้นถูกวาดทีละเส้น = เทคนิค `stroke-dasharray` + `stroke-dashoffset` ไล่จากความยาวเส้นเต็มลงเป็น 0
- ตัวหนังสือไทยขึ้นตามจังหวะเสียงพากย์ (ต้องรู้เวลาของแต่ละประโยค — ข้อ 2)
- ใส่ภาพประกอบ/asset เสริมตามเนื้อเรื่อง
- ทำไมเหมาะ: ตัวละครเรียบมาก หน้าไม่เพี้ยนข้ามฉาก อยากเปลี่ยนท่า/คำพูดก็แก้เฉพาะจุด

### 2.3 ลดต้นทุน token / ทำให้งานต่างจากคนอื่น

ข้อเสนอจากโพสต์: อย่าให้ agent เขียนทุกอย่างใหม่ทุกคลิป ให้มีชุดเครื่องมือ JS ที่ใช้ซ้ำ

- ฟังก์ชันวาด (ตัวละคร, ลูกศร, กล่องข้อความ, กราฟนับเลข) + template ฉากมาตรฐาน → agent เขียนแค่สเปกฉาก (ข้อ 2.1)
- ต่อ API ภายนอก: เสียงพากย์ (เขาแนะนำ PaxaLabs ของคนไทย — ยังไม่ได้ทดสอบ), สร้างภาพประกอบ
- งานเราต่อยอดได้จากของที่มีแล้ว: ภาพประกอบ Canva AI (`canva-handover.md`) · ลายพื้น (`pattern-library.md`) · หัวเรื่อง (`typography-library.md`)

## 3. เครื่องมือ render (ตัวเลือก — ยังไม่ได้เลือกใช้)

| ตัวเลือก | ลักษณะ | หมายเหตุ |
|---|---|---|
| Playwright/Chromium + ffmpeg (ทำเอง) | เปิด HTML ทีละเฟรม ตั้งเวลา animation ให้ตรงเฟรม → จับภาพ → ffmpeg รวม | ไม่มี dependency ใหม่ คุมได้หมด · ต้องหยุดเวลาเอง (ห้ามพึ่ง `requestAnimationFrame` จริง ไม่งั้นเฟรมหลุด) |
| HyperFrames (HeyGen) | เฟรมเวิร์ก HTML → MP4 มีสกิล `motion-graphics` ให้ agent | ติดตั้ง `npx skills add https://github.com/heygen-com/hyperframes --skill motion-graphics` (จากผลค้นหา ยังไม่ได้ลอง) |
| Remotion | เขียนฉากเป็น React แล้ว render | **ตรวจสัญญาอนุญาตก่อนใช้ในงานหน่วยงาน** (มีเงื่อนไขตามขนาด/ประเภทองค์กร) |

สิ่งที่ genhaha ใช้จริง: **ยังไม่ยืนยัน** (โพสต์บอกแค่ว่ามีทั้งแบบ Skills และ MCP รองรับ Claude/Gemini/Codex/ChatGPT/Cursor/Copilot/Antigravity และผู้เขียนเทสว่า Claude ให้ผลดีสุด)

## 5. กฎของเราที่ต้องทับลงไปเมื่อทำจริง

- สี/ฟอนต์/โลโก้มาจาก `design-system` (`skins/aritc/social-cover.json`, `paint/`) ห้ามเดา — ดู `design-system/SKILL.md`
- ข้อความไทย: ห้าม `text-transform: uppercase` และ `letter-spacing` เกิน `0.08em` (สระ/วรรณยุกต์หลุด — กฎ design-system ข้อ 9)
  ต้องโหลดฟอนต์ไทยแบบไฟล์ในเครื่องก่อน render เฟรมแรก ไม่งั้นเฟรมต้น ๆ เป็นฟอนต์สำรอง
- ไอคอนใช้ lucide ห้าม emoji (หน้าตาเปลี่ยนตามเครื่องที่ render — กฎข้อ 12)
- ขยับด้วย `transform` / `opacity` เป็นหลัก (กฎข้อ 8) — พรีวิวในเบราว์เซอร์ลื่น และเฟรมไม่กระตุก
- ภาษาในบท/ซับ: ผ่าน `prose-cleaner` / `thai-language-guard` ถ้าเป็นสื่อความรู้ทางการ
- ตัดต่อปิดงานใน Premiere: `desk-utils/tools/premierekit` (ซับ .srt, timeline XML) ใช้ต่อจาก MP4 ได้
- ลงหลักฐาน: คลิปที่คิดเองตามโจทย์ = KPI กราฟิก (`kpi-report.mjs --kpi design`) · คลิปแนะนำทรัพยากรที่คนอื่นส่งเนื้อหามา = `wp-it-05_gasidid` · ก้ำกึ่งถามเจ้าของ (ตาม `dev-tools/CLAUDE.md`)
