## 1. ออก PDF

```powershell
$e = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
$u = ([System.Uri]"<path>\deck.html").AbsoluteUri
Start-Process $e -ArgumentList "--headless=new","--disable-gpu","--no-pdf-header-footer","--virtual-time-budget=15000","--user-data-dir=$env:TEMP\edgepdf","--print-to-pdf=`"<out>.pdf`"",$u -Wait
```
* สไลด์ `@page{size:1280px 720px;margin:0}` · ใบงาน `@page{size:A4}`
* HTML โหลด Sarabun จาก Google Fonts ได้ — PDF ฝังฟอนต์ให้เอง จึงใช้ offline ได้ (เช็กด้วย pymupdf ว่าในไฟล์มี `Sarabun-*`)
* เขียนสคริปต์แก้ไฟล์ที่มีภาษาไทย/backslash เป็นไฟล์ `.py` แล้วรัน — ห้าม heredoc ใน bash (ตีความ `\u` ผิด)

## 3. Design

### 3.2 Typography
* **Font-family:** `'Sarabun'` เท่านั้น (ตาม design-system `paint/aritc.css`) fallback `'Leelawadee UI'`, `'Tahoma'` — ห้ามใช้ Prompt
* **Header ขนาดใหญ่ (H1/Hero):** 48–72px ตัวหนา (Weight 700-800)
* **หัวข้อสไลด์ (H2):** 36–52px
* **เนื้อหา (Body):** 18–26px line-height 1.6–1.8
* **กันสระ/วรรณยุกต์ชนกัน (บังคับ):** ไทยซ้อนสระบน + วรรณยุกต์ (เช่น "ตั้ง" "ไม้") สูงเกินกรอบบรรทัด
  * หัวเรื่องทุกขนาด line-height ≥ **1.4** (ห้าม 1.2–1.3 แม้ design-system ตั้ง leading-tight ไว้ — นั่นสำหรับ UI ขนาดเล็ก)
  * ป้ายเล็ก (eyebrow) ที่วางเหนือหัวเรื่อง: line-height 1.6 + margin-bottom ≥ 8px
  * ข้อความ 2 ชั้นซ้อนกันทุกจุด (ชื่อ/ตำแหน่ง, kicker/h1) ต้องมีระยะเหลือ — ตรวจด้วยคำทดสอบ "ตั้งไว้ก่อน ไม่ได้ตั้ง" ก่อนส่งมอบ

### 3.3 สไตล์ภาพรวม: มินิมอล สะอาดตา (บังคับ)
อ้างอิงระบบ `~\Documents\GitHub\design-system` (core/graphite.css, shape.css, paint/aritc.css)

**พื้นและลาย**
* พื้นสไลด์สว่าง `#f8f8f6` + ลายจุดเรขาคณิตจาง (dot grid 24px สี `#d4d4d8`)
* ของตกแต่ง = วงกลมเส้นบาง 1px / วงกลมขาวมีเงานุ่ม ที่มุมสไลด์ ไม่บังเนื้อหา
* **ห้ามพื้นเข้มเต็มหน้า** รวมถึงปกและหน้าคั่นส่วน — ใช้พื้นสว่าง + ตัวเลขส่วนในวงกลมขาว

**รูปทรง**
* การ์ด radius 24px · ชิป/แถว 14px · ป้าย/ปุ่ม เป็น pill · ขอบ 1px `#e4e4e7` · เงานุ่ม `0 20px 45px -15px rgba(0,0,0,.07)`
* **ห้ามแถบสีหนาที่ขอบซ้ายกล่อง** (border-left accent) — ดูโบราณ รก
* ห้ามระบายพื้นเขียว/แดงทั้งกล่อง กล่องเป็นพื้นขาว สถานะบอกด้วย **จุดสี / ไอคอน / ป้าย pill** เท่านั้น

**สี**
* ตัวอักษร/ปุ่มหลัก = เทาเกือบดำ `#18181b` ไม่ใช้สีแบรนด์จัด
* สีสถานะชุดอ่อน: success `#ecfdf5/#a7f3d0/#065f46` · error `#fff1f2/#fecdd3/#9f1239` · warning `#fffbeb/#fde68a/#92400e`
* สีสด (แดง/เขียว) กินพื้นที่ไม่เกิน ~10% ของสไลด์ · แถบเตือนแดงใช้เฉพาะเรื่องอันตรายจริง
* ไฮไลต์คำ = ขีดเน้นเหลืองอ่อนครึ่งล่าง ไม่ใช่ตัวสีส้ม

**ไอคอน**
* **ห้าม emoji** ในสไลด์ (หน้าตาเปลี่ยนตาม OS/ตอนพิมพ์ PDF) — ใช้ SVG เส้นแบบ lucide (check-circle, x-circle, alert) ขนาดเท่าตัวอักษร

### 3.3.1 ลายเซ็นงานผู้ใช้ (มาตรฐานอ้างอิง — ทำ Google Slides เอง)
งานต้องได้ระดับนี้ ไม่ใช่แค่ "มินิมอล"
* **หัวสไลด์:** ป้ายเล็ก (eyebrow ~18px สีเน้นหรือเทาเข้ม) → หัวเรื่องตัวหนาใหญ่ ชิดซ้ายบน · โลโก้ ARITC (PNG ใส) มุมขวาบน ถ้าเป็นงานหน่วยงาน
* **แผงกราฟิกหลัก 1 แผงต่อหน้า** กิน 35–45% ของพื้นที่ มุมมนเท่าการ์ด · เรขาคณิต + สีของธีม (ดู "กราฟิก" ด้านล่าง)
* **การ์ดขาว** มุมมนมาก ขอบบางมาก ไม่มีเงาหนัก · ช่องไฟกว้าง

### 3.6 ถ้อยคำ — ใช้คำของผู้ใช้ (บังคับ)
> หลักเดียวกับ [../Writing/5-prose-cleaner.md](../Writing/5-prose-cleaner.md): **ไม่เขียนเนื้อหาใหม่แทนผู้เขียน** จุดที่อ่านเป็นภาษา AI คือจุดที่ AI เรียบเรียงเอง
* ข้อความบนสไลด์ **ยกจาก source ตรงตัว** — ย่อได้ด้วยการตัดคำ ห้ามเขียนใหม่ ห้ามเปลี่ยนคำกริยาของผู้ใช้ (เช่น "ใช้หา...", "แปลว่า...", "ผลจะแคบลง")
* หน้าปิดท้าย "จำ 3 ข้อ" = **ประโยคของผู้ใช้เอง** เลือกจาก source/โน้ตผู้พูด (เช่น ประโยคปิดในโน้ต, คำโปรยปก) ห้ามแต่งสโลแกน
* ห้ามรูปแบบ `วลีตัวหนา — คำอธิบาย` ที่ AI ชอบใช้แทนประโยคไทยปกติ · ใช้คำเชื่อมไทย (แล้ว / ถ้า / แต่) แทนลูกศรและขีดยาวในประโยค
* **ใช้คำที่คนไทยพูดจริง** แม้คำนั้นจะมาจาก source ก็ตาม ถ้าเป็นสำนวนแปล ให้เสนอคำพูดปกติแทน เช่น ❌ "เส้นทางวันนี้" → ✅ "ขั้นตอนที่เราจะฝึกทำ" · ❌ "วิธีคิดของวันนี้"
* **ชื่อเครื่องมือ/ผลิตภัณฑ์ต้องเป็นชื่อปัจจุบัน** — ค้นเว็บเช็กก่อนถ้าไม่แน่ใจ (เช่น NotebookLM เปลี่ยนเป็น **Gemini Notebook** ตั้งแต่ 16 ก.ค. 2026 · URL `notebook.google`) ใส่ "(เดิมชื่อ …)" ครั้งเดียวในหน้าที่แนะนำเครื่องมือ
* **ชื่อคอร์ส** = แก่นของเรื่อง ไม่ใช่วิธีการ เช่น คอร์สพยาบาล = "การเข้าถึงทรัพยากรสารสนเทศของห้องสมุด" (ป้าย: คณะพยาบาลศาสตร์) ส่วน "สืบค้นฐานข้อมูล + AI" เป็นคำโปรย · ไม่แน่ใจ → ถามผู้ใช้ว่าแก่นของคอร์สคืออะไร
* ป้ายบนแผงกราฟิก / eyebrow ใช้คำจาก source หรือโน้ตผู้พูด (เช่น "พิมพ์ตามได้", "ดูผลพร้อมกัน")
* ข้อความที่จำเป็นต้องเพิ่มเอง (ป้ายขั้น, ชื่อหน้าปิด) ให้สั้นที่สุด และแจ้งผู้ใช้ในรายงานขั้น 9

## 4. Offline & สถานที่อบรม (บังคับ)

> สถานที่อบรมหลายแห่ง (เรือนจำ โรงเรียนชนบท ห้องประชุมราชการ) **ไม่มีอินเทอร์เน็ต** ถ้าไฟล์พึ่งเน็ต ฟอนต์ไทยจะไม่โหลด ตัวอักษรเพี้ยน **อ่านยาก** และบางส่วนใช้งานไม่ได้

### 4.1 ถามก่อนเริ่มทุกครั้ง (โฟลว์ขั้น 2)
ก่อนสร้างสไลด์ ให้ถามผู้ใช้ว่า **"สถานที่อบรมมีอินเทอร์เน็ตไหม?"** และ **"มีห้องคอม / ต้องทำใบงานไหม?"**
* ไม่มี / ไม่แน่ใจ → ใช้ **โหมด Offline** (ข้อ 4.2) ทันที
* มีแน่นอน → ยังแนะนำโหมด Offline เป็นค่าเริ่มต้น เพราะเน็ตหน้างานไม่แน่นอน

### 4.2 กฎโหมด Offline
1. **ตัวส่งมอบคือ PDF** — ฟอนต์ฝังในไฟล์อัตโนมัติ (ข้อ 1) · ถ้าต้องส่ง HTML ให้เปิดหน้างาน ต้องฝัง Sarabun เป็น `@font-face` base64 ห้ามพึ่ง `fonts.googleapis.com`
2. **ไฟล์เดียวจบ** — CSS, JS, รูปภาพ ฝังในไฟล์ทั้งหมด (รูปเป็น base64 หรือวาดเป็น SVG) ห้ามอ้าง CDN / URL ภายนอก
3. **ห้ามสิ่งที่ต้องใช้เน็ต** — YouTube, `<iframe>`, Google Form, แผนที่ออนไลน์, QR ที่ต้องสแกนเปิดเว็บระหว่างอบรม
4. **Fallback ฟอนต์อ่านง่าย** — `font-family: 'Sarabun','Leelawadee UI','Tahoma',sans-serif` (Leelawadee UI / Tahoma มีในทุกเครื่อง Windows)
5. **เปิดด้วยดับเบิลคลิก** — ทำงานจาก `file://` บนแฟลชไดรฟ์ได้ ไม่ต้องรันเซิร์ฟเวอร์
6. **ไฟล์สำรอง PDF** — ส่งออก PDF 16:9 คู่กันทุกครั้ง เผื่อเครื่องหน้างานเปิด HTML ไม่ได้

3. **PDF อย่างเดียว** เมื่อไม่มีลิงก์ที่สำคัญจริง

**ใส่ / ไม่ใส่**
* ✅ PDF สไลด์ 1 ไฟล์ ข้อความ "สไลด์ประกอบการอบรม" — ห้ามเลขเวอร์ชัน

* ❌ โจทย์เกม / ด่าน · ❌ ใบงาน — อยู่ใน LibPlay
* ❌ ข้อความที่มีในสไลด์อยู่แล้ว (สรุป, จำ 3 ข้อ, ขั้นตอน)
* **ผู้โพสต์ = บัญชีจริงของผู้ใช้** (ชื่อ + รูปจาก users ผ่าน `ownerEmail`) ห้ามพิมพ์ชื่อเองในโน้ต — `publish-lesson.ts` ทำให้อัตโนมัติ · ห้ามใช้ `noteboard_publish.py` (API) เพราะชื่อผู้โพสต์ผิด
* แก้ห้องที่มีอยู่: `bun scripts/tidy-board.ts <spec.json>` — เปลี่ยน mode/คอลัมน์ · ย้ายลงถังขยะ (กู้คืนได้) · แก้ข้อความ · ปักหมุด · `ownerEmail` = ผูกโน้ตผู้จัดกลับเป็นบัญชีจริง

**แก้เนื้อหาห้องที่ขึ้นแล้ว (ทางลัด — ห้ามเขียนสคริปต์ SQL เอง ใช้ `tidy-board.ts` ตัวเดียว)**

| อยากแก้ | spec.json (`boardId` = เลขยาวของห้อง) |
|---|---|
| ดูโน้ตทั้งห้อง (id · คอลัมน์ · หมุด · ถูกลบ · ไฟล์) — **รันก่อนทุกครั้ง** | `{"list":true}` |
| แก้ข้อความโน้ต | `{"update":{"<id>":{"text":"..."}}}` |
| แก้คำเดียวกันทุกโน้ต (เช่น "เล่มเดียวกับ") | `{"replaceText":{"from":"...","to":"..."}}` |
| เพิ่มโน้ตผู้จัด (ลิงก์ Gem, หัวข้อ) | `{"ownerEmail":"...","add":[{"column":"docs","color":"blue","text":"...","pin":true}]}` |
| กู้โน้ตที่ถูกลบ / ลบ | `{"restore":["<id>"]}` · `{"trash":["<id>"]}` |

* ต้องเปิด tunnel `127.0.0.1:3306` ก่อน (เช็ก `(echo > /dev/tcp/127.0.0.1/3306)`) ปิดอยู่ → บอกผู้ใช้ให้เปิด
* **ไฟล์ในห้อง (สไลด์ / ไฟล์แจก)**: ชื่อไฟล์บน server ดูจากคอลัมน์ไฟล์ของ `list` → build ใหม่ → `cp` ทับ `backend/uploads/<ชื่อเดิม>` → `scp` ด้วย alias `nsru72` (ขั้น 5 ด้านล่าง) → เช็ก 200 และขนาดตรงกับในเครื่อง · ไม่ต้องแก้ DB เพราะชื่อเดิม
* `.md` server เสิร์ฟไม่ได้ (404) → อัปเป็น `.txt` ชื่อเดิม
* โน้ตที่ `DELETED` แต่ผู้จัดไม่ได้ลบเอง = ผู้ใช้ลบจากหน้าเว็บ **ห้ามกู้เอง** บอกผู้ใช้ก่อน
* ข้อความโน้ตต้องผ่าน `lint_thai.py` (เขียนลง .txt ชั่วคราวแล้วรัน) ก่อน update
* เช็กผลในห้องจริงด้วยเบราว์เซอร์ (`document.body.innerText`) ก่อนรายงาน
* **โน้ตหัวข้อรายงาน (ผู้ใช้กำหนด)**: บรรทัดสาขา + ชื่อหัวข้อ → `ประเด็นที่ต้องศึกษา` 1..n → `คำค้น` 1..n **แยกเป็นอีกส่วน เลขข้อตรงกับประเด็น** · คำค้นภาษาไทยล้วน ไม่มีอังกฤษ ไม่มีสูตรบูลีน (โปรแกรมค้นฉลาดพอ)
* **Gem วางแผนค้น**: คำสั่ง Gem อยู่ในไฟล์แจก `handouts/วางแผนค้น-gem.md` ผู้ใช้สร้าง Gem แล้วแชร์ลิงก์ → `add` เป็นโน้ตปักหมุดในคอลัมน์เอกสาร (Gem ฟรีทุกบัญชี แชร์ลิงก์ได้ · ทักษะใน Spark ต้องมี Pro ใช้กับนิสิตไม่ได้)
* **ไฟล์ตรวจแหล่งใน Notebook**: ไม่ต้องลบเปเปอร์ที่ไม่ตรง ไฟล์ตรวจให้พรอมท์ที่ระบุไฟล์ที่ใช้และไม่ใช้ (ขั้นที่ 3 ของ `ตรวจแหล่งข้อมูล.md`)

**ขั้นตอน**
1. ทำ PDF สไลด์เสร็จ ผ่านการตรวจ (ข้อ 2)
2. เขียน `lesson.json` → รัน `publish-lesson.ts`
3. สคริปต์พิมพ์ `board id`, รหัสห้อง, URL และรายชื่อไฟล์ใน `backend/uploads`
4. ใส่รหัสห้องในหน้าปิดท้าย (`build_pdf.py --room "ห้องกิจกรรม NoteBoard รหัส XXXXXX"`) แล้วคัดลอก PDF ใหม่ทับไฟล์ใน `backend/uploads/<ชื่อที่สคริปต์พิมพ์>`
5. **ส่ง PDF ขึ้น server เอง** ไม่ต้องรอผู้ใช้กด sync (host alias `nsru72` ตั้งไว้ใน `~/.ssh/config` ของเครื่อง — ที่อยู่ server ผู้ใช้ และ key ไม่เก็บใน repo นี้):
   ```powershell
   scp -o BatchMode=yes -p "<noteboard>\backend\uploads\<file>.pdf" "nsru72:C:/Websites/apps/noteboard/backend/uploads/<file>.pdf"
   ```
   ไม่มี alias ในเครื่อง → ถามผู้ใช้ ห้ามเดาที่อยู่ server
6. เช็ก `https://noteboard.nsru.ac.th/uploads/<file>.pdf` ต้องตอบ **200** ก่อนรายงานว่าเสร็จ (404 = ยังไม่ขึ้น)
7. **ทำปกห้อง (บังคับ ห้ามปล่อยปกค่าเริ่มต้น / ภาพสไลด์สุ่ม)** — ปกโชว์เป็นการ์ด 16:9 (~300px) และรูปย่อ 64px จึงออกแบบแยกจากปกสไลด์:
   ```powershell
   python ~\Documents\GitHub\academicforward\Designing\scripts\build_cover.py `
     --title "ชื่องานสั้น|*บรรทัดที่ 2 คำเน้น*" --kicker "หน่วยงาน/กลุ่มผู้เรียน" `
     --theme <ธีมเดียวกับสไลด์> --icon <shield|search|book|sparkles|library|smartphone|graduation|presentation> `
     --out <โฟลเดอร์งาน>\cover.jpg
   cd ~\Documents\GitHub\noteboard; bun backend/scripts/set-cover.ts <รหัสห้อง> <โฟลเดอร์งาน>\cover.jpg
   ```
   * หัวเรื่อง ≤ 2 บรรทัด ใช้ `|` ตัดบรรทัดเอง (ห้ามปล่อยคำหลุดท้ายบรรทัด) · ไม่มีเลขหน้า/ชื่อวิทยากร/ข้อความเล็ก
   * เปิดดู `cover.jpg` ก่อนตั้งทุกครั้ง · ปกเดิมสำรองอัตโนมัติเป็น `cover.jpg.prev-<รหัส>.json`
   * URL ห้อง = `https://noteboard.nsru.ac.th/board/<board id>` → ใช้เป็นหลักฐาน KPI ขั้น 10

**ห้าม**
* ห้ามใช้ `externalInjection` (ปิดแล้ว ต้องมี token ผู้จัด)
* ห้ามแก้ `.env` / config บน server · ห้ามแตะระบบล็อกอิน
* งานไม่มีเน็ต (เรือนจำ) ไม่ต้องสร้างห้อง เว้นผู้ใช้สั่ง

## 6. ชุดบทเรียนสำหรับ LibPlay (เก็บทุกงาน — ย้ายเข้าเมื่อ LibPlay เสร็จ)

> LibPlay แบ่ง 2 ส่วน **บทเรียน** (สไลด์ + ใบงาน) และ **เกม** — ทุกชิ้น **จับคู่กัน** เหมือน HTML hub ดั้งเดิมของผู้ใช้ (ถอดแบบไว้แล้วใน `libplay/frontend/src/features/notebooklm/`: SlideDeck · Handouts · GameBoard)
> NoteBoard = ห้องให้ผู้เรียนเข้าเห็นสไลด์ + โพสต์ · เกมและใบงานไม่ขึ้น NoteBoard

**ทุกโฟลเดอร์งานต้องมีครบ 3 ชิ้นที่จับคู่กัน**

| ไฟล์ | ส่วนใน LibPlay | ตรงกับ (ถอดแบบ) |
|---|---|---|
| `deck.html` | บทเรียน → สไลด์ | `SlideDeck` / `data/slides.ts` |
| `worksheet.html` | บทเรียน → ใบงาน | `Handouts` / `topics.ts handout` |
| `game.json` | เกม | `GameBoard` / `topics.ts challenges` |
| `lesson.json` | ห้อง NoteBoard (+ `board.code` หลังสร้าง) | activity ขั้น `noteboard` |

**game.json**
```json
{
  "status": "draft | empty | approved",
  "mission": "ชื่อภารกิจ",
  "pairsWith": {"deck": "deck.html", "worksheet": "worksheet.html"},
  "challenges": [
    {"stage": "ด่านที่ 1", "title": "...", "tool": "...", "slides": [3,4], "prompt": "...", "win": "+10"},
    {"stage": "BOSS", "boss": true, "title": "...", "slides": [9], "prompt": "...", "win": "+50"}
  ]
}
```
* `slides` = เลขหน้าสไลด์ที่ด่านนั้นใช้ (จับคู่บทเรียน ↔ เกม)
* source มีโจทย์เกม → ยกตรงตัว `status: approved`
* source ไม่มี → `status: empty` แล้ว **ถามผู้ใช้** ว่าจะให้ร่างไหม · ร่างเอง = `draft` และแจ้งในรายงานขั้น 9
* ใบงานกับเกมต้องอ้างเนื้อหาในสไลด์ชุดเดียวกันเท่านั้น
