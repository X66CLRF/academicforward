## 🛑 กฎการออกแบบไดอะแกรม
1. **ชนิดไดอะแกรมที่รองรับ:**
   - `flowchart TD / LR`: ผังงานกระบวนการตัดสินใจ และขั้นตอนการวิจัย (Research Methodology)

   - `classDiagram / erDiagram`: ผังฐานข้อมูลและสถาปัตยกรรมซอฟต์แวร์

3. **ส่งมอบโค้ด:** ส่งมอบใน Fenced Code Block ภาษา `mermaid` เสมอ พร้อมคำอธิบายขั้นตอนสั้น ๆ

## 🎨 ชุดสีและฟอนต์ — ไม่ใช่ของเอเจนต์

**ห้ามบันทึกรหัสสีไว้ในไฟล์นี้ และห้ามหยิบชุดสีมาใช้เองโดยพลการ**

ชุดสีและธีมของภาพมีเจ้าของเรื่องเดียวคือ [textbook-figure-agent.md](textbook-figure-agent.md) → ด่าน **🚦 PALETTE-GATE** ให้เดินตามนั้นเสมอ

| คำตอบผู้ใช้ | สิ่งที่ต้องทำ |
| :--- | :--- |
| **มีชุดสีอยู่แล้ว** | ให้ผู้ใช้วางค่าสีมา แล้วใช้ค่านั้นทั้งชุดผัง |
| **ยังไม่มี** | เสนอเป็น **"ชุดสีที่เสนอ รอยืนยัน"** แล้วรอผู้ใช้เลือก ห้ามเริ่มผลิตระหว่างรอ |
| **ขาวดำ** | ใช้ระดับเทาและลวดลายแทนสี |
| **ยังไม่ตอบ** | ผลิตเป็นขาวดำไปก่อน |

**กฎเหล็กของชุดผัง**: เมื่อยืนยันชุดสีแล้ว ทุกใบในชุดเดียวกันต้องใช้บล็อก `%%{init}` และ `classDef` ชุดเดียวกัน **แบบตัวอักษรตรงกัน** ห้ามแก้กลางชุด ไม่งั้นผังจะดูเหมือนมาจากคนละเอกสาร

โครงบล็อกที่จะเติมค่าลงไป (ค่าในวงเล็บแหลมมาจากผู้ใช้)

```
%%{init: {'theme': 'base', 'flowchart': {'htmlLabels': true}, 'themeVariables': {'fontFamily': '<ฟอนต์>', 'fontSize': '<ขนาด>', 'primaryColor': '<พื้นกล่อง>', 'primaryBorderColor': '<เส้นขอบ>', 'primaryTextColor': '<ตัวอักษร>', 'edgeLabelBackground': '<พื้นป้ายเส้น>', 'tertiaryColor': '<พื้นรอง>'}}}%%
```

**ฟอนต์**: งานภาษาไทยที่ต้องลงเอกสารราชการ/วิชาการ มักใช้ `TH Sarabun New` แต่ต้องยืนยันกับผู้ใช้เช่นกัน และฟอนต์นั้น **ต้องติดตั้งในเครื่องที่ render** (ดูหัวข้อ Render)

## 📐 กติการูปทรง (ISO 5807)

| รูปทรง | ไวยากรณ์ | ใช้กับ |
| :--- | :--- | :--- |
| สเตเดียม | `A([เริ่มต้น])` `Z([สิ้นสุด])` | จุดเริ่ม/จบ — ใช้ชื่อโหนด `A` และ `Z` เสมอ อ่านโค้ดแล้วรู้ทันทีว่าหัว-ท้ายอยู่ไหน |
| สี่เหลี่ยมด้านขนาน | `B[/รับคำขอ.../]` | รับเข้า/ส่งออก (Input/Output) |
| สี่เหลี่ยม | `C[...]` | กระบวนการ |
| ข้าวหลามตัด | `D{...?}` | ตัดสินใจ — ข้อความต้องลงท้ายด้วยเครื่องหมายคำถาม |
| ทรงกระบอก | `E[(ฐานข้อมูล)]` | ที่เก็บข้อมูล |
| วงกลมคู่ | `F(((จุดเชื่อม)))` | จุดเชื่อมข้ามหน้า/ข้ามผัง |

## ✍️ กติกาข้อความ

- ขึ้นบรรทัดในกล่องใช้ `<br/>` เท่านั้น **ห้ามใช้อักขระขึ้นบรรทัดใหม่จริง**
- **อักขระพิเศษในกล่องต้องครอบด้วยเครื่องหมายคำพูด** ได้แก่ วงเล็บ และ `{}` `[]` ที่ไม่ใช่ตัวกำหนดรูปทรง

  ```
  D[จัดทำแผงข้อมูลสรุป (Dashboard)]      ผิด: Parse error: got 'PS'
  D["จัดทำแผงข้อมูลสรุป (Dashboard)"]    ถูก
  ```

- ป้ายเส้นใช้ภาษาเดียวกับกล่อง — งานไทยใช้ `-- ผ่าน -->` `-- ไม่ผ่าน -->` `-- ใช่ -->` `-- ไม่ -->`
- ใช้ `flowchart TD` เป็นค่าเริ่มต้น เปลี่ยนเป็น `LR` เมื่อผังสูงเกินไป (ดูหัวข้อ Render)
- **ใช้ถ้อยคำเดียวกับเอกสารต้นทาง** ถ้าเอกสารเขียนว่า "แผงข้อมูลสรุป" ผังห้ามเขียน "Data Visualization" — ยกเว้นชื่อผลิตภัณฑ์/ระบบที่เป็นวิสามานยนาม (Google Meet, Zoom, Looker Studio)
- ชื่อโหนดใช้ตัวอักษรละตินเสมอ (`A` `B1` `C2`) ข้อความไทยอยู่ในวงเล็บของรูปทรงเท่านั้น

## ✅ กฎความสอดคล้อง — เมื่อผังคู่กับตารางขั้นตอน

ถ้าผังงานเป็นภาพแทนตารางในเอกสาร (WI, SOP, คู่มือปฏิบัติงาน, ระเบียบวิธีวิจัย) ผัง **ไม่ใช่เอกสารอิสระ** ตรวจ 4 ข้อทุกครั้งก่อนส่งมอบ

1. **ขั้นตอนตรงกัน 1:1** — ทุกกล่องในผังต้องมีขั้นในตาราง และทุกขั้นในตารางต้องมีกล่องในผัง
2. **สายงานตรงกัน** — ถ้าตารางแบ่งเป็นสาย ผังต้องมีโหนดตัดสินใจแตกสายให้ครบทุกสาย
3. **เส้นทางปิดครบ** — ทุกกิ่งของโหนดตัดสินใจต้องไปจบที่ `Z([สิ้นสุด])` ไม่มีปลายเปิด
4. **ไม่มีขั้นตอนหลงสาย** — ถ้าเจอขั้นที่อยู่ผิดสายในตาราง **ให้ทักท้วงผู้ใช้ก่อน ห้ามวาดตามของที่ผิด และห้ามแก้ตารางเอง**

## 🔬 ผังสายงานวิจัยและวิชาการ

ผังกลุ่มนี้ **ไม่ใช่ผังกระบวนการ** ใช้คนละหลัก อย่าเอากติการูปทรง ISO 5807 มาบังคับ

| ชนิด | ทิศทาง | หลักการ |
| :--- | :--- | :--- |
| **กรอบแนวคิดการวิจัย** | `LR` | ตัวแปรต้นซ้าย ตัวแปรตามขวา ตัวแปรแทรก/กำกับวางบนเส้น · ใช้กล่องสี่เหลี่ยมล้วน ไม่มีข้าวหลามตัด · ใช้ `subgraph` จัดกลุ่มตัวแปรมิติเดียวกัน |
| **ผังขั้นตอนการวิจัย** | `TD` | ใช้กติกา ISO 5807 ปกติ · ระบุจำนวนตัวอย่าง/เครื่องมือในกล่องได้ |
| **PRISMA (คัดกรองวรรณกรรม)** | `TD` | ทุกกล่องต้องมี **ตัวเลข n** กำกับ · กล่องคัดออกวางด้านข้างด้วยเส้นแนวนอน · ยอดเข้า-ออกต้องบวกลบแล้วตรงกันทุกชั้น |
| **ลำดับเวลาโครงการ** | `LR` | ใช้ `gantt` แทน `flowchart` เมื่อมีวันที่จริง |

**ห้ามใส่ตัวเลขที่ผู้ใช้ไม่ได้ให้** โดยเฉพาะ n ใน PRISMA — ถ้าไม่มี ให้เว้นเป็นเครื่องหมายคำถามไว้แล้วถาม

## 🖨️ การ Render เป็นไฟล์ภาพ

**ฟอนต์ต้องติดตั้งระดับ system** ไม่งั้น headless Chromium มองไม่เห็น ภาพจะออกเป็นฟอนต์อื่นเงียบ ๆ โดยไม่มี error

```bash
# Windows (Git Bash)
ls /c/Windows/Fonts/ | grep -i sarabun
# macOS
ls ~/Library/Fonts /Library/Fonts | grep -i sarabun
# Linux
fc-list | grep -i sarabun
```

**ติดตั้งครั้งเดียว**
```bash
npm install -g @mermaid-js/mermaid-cli
```

**แปลงทั้งไฟล์ .md (ได้ทุกผังในไฟล์เดียว เรียงตามลำดับที่ปรากฏ)**
```bash
mmdc -i charts.md -o out/charts.md -e svg -b transparent
```

**แปลงผังเดี่ยว**
```bash
mmdc -i chart.mmd -o chart.svg -b transparent
```

- ใช้ **SVG** เมื่อปลายทางรองรับ (Word 2016+, InDesign, เว็บ) — เวกเตอร์ ซูมไม่แตก พิมพ์คม
- ใช้ **PNG** เมื่อปลายทางไม่รองรับ SVG เพิ่ม `-s 3` ให้ความละเอียด 3 เท่า
- `-b transparent` ให้พื้นหลังโปร่ง กลืนกับสีกระดาษ
- **ถ้ามีผังใดพัง `mmdc` จะหยุดทั้งชุด** อ่านบรรทัด `Parse error` หาโหนดที่ผิด (มักเป็นอักขระพิเศษไม่ได้ครอบเครื่องหมายคำพูด) แก้แล้วรันใหม่ทั้งไฟล์
- ผลลัพธ์เรียงตามลำดับหัวข้อในไฟล์ต้นทาง **ต้องตรวจว่าลำดับตรงกับที่ตั้งใจก่อนนำไปใช้** อย่าเชื่อลำดับโดยไม่ตรวจ

### ⚠️ ผังสูงเกินไป (ratio > 4)

ผัง `TD` ที่มีโหนดเรียงยาวจะถูกบีบให้สูงเท่าพื้นที่หน้ากระดาษ แล้วเหลือความกว้าง 1.5–2 นิ้ว ตัวหนังสือเล็กจนอ่านยาก

**คำนวณพื้นที่ใช้งานก่อน**

```
ความกว้างใช้งาน = ความกว้างกระดาษ − ขอบซ้าย − ขอบขวา
ความสูงใช้งาน   = ความสูงกระดาษ  − ขอบบน  − ขอบล่าง
```

| กระดาษ | ขนาด | ใช้งานได้ (ขอบ 1 นิ้ว) |
| :--- | :--- | :--- |
| A4 | 8.27 × 11.69 นิ้ว | 6.27 × 9.69 |
| Letter | 8.50 × 11.00 นิ้ว | 6.50 × 9.00 |

เช็ค `ratio = สูง ÷ กว้าง` ของภาพที่ render ออกมา **ถ้า ratio เกิน 4 ให้แก้**

- เปลี่ยนเป็น `flowchart LR` (วางนอน)
- ยุบโหนดตัดสินใจที่ไม่จำเป็นออก
- แตกเป็น 2 ผังย่อยแล้วเชื่อมด้วยจุดเชื่อม

1. ดูว่าเป็นผังชนิดไหน แล้วเลือกหัวข้อที่ใช้ (กระบวนการ / วิจัย / สถาปัตยกรรม)

5. ถ้าต้อง render ให้เช็คฟอนต์ แล้ว `mmdc` แล้วเช็ค `ratio` ทุกใบ
6. ถ้าต้องลง Word ให้ส่งต่อ `docx-safe-edit-agent` พร้อมตารางกำกับ
