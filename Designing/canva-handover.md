# canva-handover — ส่งงานกราฟิก/สไลด์ขึ้น Canva แบบแยกชั้น ให้ผู้ใช้แก้ร่วม

> ใช้ร่วมกับ: [social-graphic-agent.md](social-graphic-agent.md) (โพสต์ 2160) · [slide-hub-agent.md](slide-hub-agent.md) (สไลด์) · งานกราฟิกอื่นทุกงานที่ผู้ใช้จะแก้ต่อ
> ที่มา: ผู้ใช้สั่ง 2 ต.ค. 69 — "คุณทำแล้วแก้ได้คนเดียว ผมจะมีส่วนร่วมในการแก้" · งานต้นแบบ: วารสาร ต.ค. 69 (Canva `DAHW0n6_UT0` หน้า 11–15)
> **เวอร์ชัน**: v1.1 (2569-10-05)

## 0. กฎเหล็ก: ทุกงานกราฟิกจบที่ Canva แยกชั้น (ผู้ใช้ย้ำ 5 ต.ค. 69 หลังงานล่าสุดแก้ต่อไม่ได้)

1. **ปลายทางของกราฟิกทุกชิ้น = ไฟล์ Canva ที่แก้ได้** ไม่ใช่ png/ภาพที่เอเจนต์เรนเดอร์เอง · ภาพเรนเดอร์ใช้เป็น "ร่างตรวจตา" ใน `_ไฟล์ทำงาน\` เท่านั้น
2. **แยกชั้นอย่างน้อย**: พื้นหลัง/ลาย (จาก [pattern-library.md](pattern-library.md) เป็นชั้นเดียวแยกต่างหาก) · ภาพจริง · กรอบ/การ์ด · **ตัวอักษรแต่ละก้อนเป็นข้อความจริง** · โลโก้ — ตัวอักษรที่เป็นรูปแก้ไม่ได้ ถือว่างานล้ม
3. **ด่านก่อนบอกว่าเสร็จ** (ทำทุกครั้ง ข้ามไม่ได้): เปิดไฟล์ Canva ที่ commit แล้ว `read-design` ตรวจว่า (ก) ข้อความแต่ละก้อนเป็น text element (ข) ย้าย/ลบพื้นหลังแยกได้ (ค) ไม่มีชั้นไหนเป็นภาพเต็มหน้าที่มีตัวอักษรรวมอยู่ — ไม่ผ่านข้อใดให้ทำซ้ำ ไม่ใช่ส่งลิงก์ไปก่อน
4. **ขึ้น Canva ไม่ได้ (MCP ล้ม/โควตา)** → บอกผู้ใช้ทันทีพร้อมเหตุผล · **ห้ามวาง png/ไฟล์ผลงานลงโฟลเดอร์รอบแทน** เพราะ libdesk (เมนูงานสื่อ) ตีความ png ในโฟลเดอร์รอบว่า "ผลิตเสร็จ" และเปิดปุ่มแจ้งส่งงาน
5. **ไฟล์ร่าง/ไฟล์เทคนิคทั้งหมด** (png ร่าง, SVG ต้นฉบับ, handover.md) วางใน `_ไฟล์ทำงาน\` ตั้งแต่ต้น ไม่วางชั้นรอบ — ตามข้อ 1.3
6. ผู้ผลิตตัดสิน "เสร็จ/ยังไม่เสร็จ" เอง: ถ้า libdesk ขึ้น "ผลิตเสร็จ" ทั้งที่ผู้ใช้ยังไม่โอเค ผู้ใช้กดปุ่ม "ยังไม่โอเค — กลับเป็นกำลังผลิต" บนการ์ดได้ (สถานะนี้ชนะการเดาจากไฟล์ และไม่เปลี่ยนเองเมื่อมีไฟล์ใหม่) — เอเจนต์ห้ามกดแทนผู้ใช้

## 1. กติกาหลัก

1. **ออกแบบเสร็จ → บันทึกลง Canva เลย → ส่งลิงก์** ไม่ต้องรออนุมัติภาพก่อน `commit` (ผู้ใช้อนุญาตถาวร)
   - หน้า/ชิ้นที่ผู้ใช้แก้เองแล้ว: ถามก่อนแก้ทับ
   - ก่อนแก้ทุกครั้ง `read-design` ดูของล่าสุดก่อน (ผู้ใช้อาจแก้ไปแล้ว)
   - ส่งลิงก์หลัง `commit` เท่านั้น — ร่างที่ยังไม่ commit ผู้ใช้มองไม่เห็น
2. **รอบแก้ = เพิ่มหน้าต่อท้าย** (`add_page` ขนาดจริง) ไม่ทับหน้าเดิม ผู้ใช้เทียบได้ · ตั้งชื่อหน้า `v<รอบ>-<ลำดับ>`
3. **แยกชั้นทุกชิ้น** — ห้ามวาดทั้งหน้าเป็นภาพเดียว ผู้ใช้ต้องย้าย/ขยาย/ซ้อน/ลบได้ทีละชิ้น
4. **ขนาดจริงเสมอ** โพสต์ 2160×2160 · สไลด์ตามขนาดที่ใช้จริง — ห้ามทำหน้า 1080 แล้วให้ผู้ใช้ขยายตอนดาวน์โหลด (เบลอ)

## 1.1 จัดระเบียบงานใน Canva (ผู้ใช้สั่ง 2 ต.ค. 69 — ไม่ชอบลิงก์กระจาย)

- **1 ลิงก์ (design) ต่อเดือน ต่อภาระงาน ต่อขนาด** — งานใหม่/รอบแก้ = เพิ่มหน้าต่อท้ายในลิงก์เดิม ไม่สร้างลิงก์ใหม่
  - หาลิงก์ของเดือน: ดูใน `handover.md` รอบก่อนของเดือนเดียวกัน หรือค้นชื่อใน Canva · ยังไม่มี = สร้างใหม่แล้ว `update_title` ตามรูปแบบทันที
- **ชื่อลิงก์:** `ปปปป-ดด <ภาระงาน> <ขนาด>` — ผู้ใช้พ่วงขนาดท้ายชื่อเสมอ
  | ภาระงาน | ตัวอย่าง |
  | :--- | :--- |
  | แนะนำทรัพยากร (`wp05`) | `2569-10 แนะนำทรัพยากร 2160x2160` |
  | สื่อออกแบบเอง (KPI design) ชิ้นเดี่ยว | `2569-10 สื่อออกแบบ A4` · `2569-10 สื่อออกแบบ 2160x2160` |
  | **สไลด์ / พาวเวอร์พอยต์ (หลายหน้าในตัวอยู่แล้ว)** | **ชื่อเฉพาะ 1 ลิงก์ต่อ 1 ชุด ไม่รวมลิงก์เดือน:** `ปปปป-ดด <ชื่อเรื่องไทย> - สไลด์ 1920x1080` เช่น `2569-09 มือถือเรา ใครคุม - สไลด์ 1920x1080` (ชื่อเรื่องเดียวกับไฟล์แจก PDF ใน `slide-hub-agent.md` 3.4) |
  - ขนาด: กระดาษใช้ชื่อมาตรฐาน (A4, A3, A2…) แนวนอนต่อ `-แนวนอน` · ดิจิทัลใช้ `กว้างxสูง` px (ตัว x เล็ก)
  - คนละขนาด = คนละลิงก์ (เดือนเดียวกันมีป้าย A4 กับโพสต์จัตุรัส = 2 ลิงก์)
- **ชื่อหน้า** (`add_page` ใส่ `title` หรือ `update_title`): ต้องระบุชื่อเรื่อง/ชื่อทรัพยากรต่อท้ายเสมอ เพื่อให้รู้ชัดเจนว่าเป็นของใคร/เล่มไหน: `<หมวด/งาน> รอบ<n> · v<รอบแก้>-<ลำดับ> (<ชื่อเรื่อง/ทรัพยากร>)` เช่น `นิยาย รอบ1 · v1-2 (วาฬยักษ์ไม่รู้จักพอ)` หรือ `วารสาร รอบ1 · v4-2 (เกษตรผสม-ผสาน)` (หน้าแรกใส่ `(หน้าชุด)`)
- **การส่งขึ้น Canva:** ทุกงานแนะนำทรัพยากร เมื่อเรนเดอร์ PNG เสร็จแล้ว ต้องส่งขึ้น Canva ดีไซน์ประจำเดือน (`ปปปป-ดด แนะนำทรัพยากร 2160x2160`) ผ่าน Canva MCP เสมอ (ใน Antigravity ให้เรียกผ่าน `claude -p` อัตโนมัติ)
- หน้าที่ผู้ใช้เลือกใช้จริง: ผู้ใช้ต่อท้ายชื่อหน้า ` ✓` → รอบถัดไปใช้หน้านั้นเป็นภาพอ้างอิงสไตล์
- API ลบหน้า/ย้ายโฟลเดอร์ไม่ได้ — หน้าร่างเก่าผู้ใช้ลบเอง (ห้ามคิดว่าหน้ายังอยู่ — `read-design` ก่อนทุกครั้ง)
- `handover.md` ของรอบ: จดลิงก์เดือน + ช่วงหน้า/ชื่อหน้าของรอบนั้น (ที่อยู่ไฟล์ + หัวข้อบังคับ ดู 1.3)

## 1.3 โฟลเดอร์รอบใน Drive + `handover.md` (ผู้ใช้สั่ง 2 ต.ค. 69)

**คนอื่นเปิดโฟลเดอร์รอบต้องไม่งง** — ชั้นบนสุดของโฟลเดอร์รอบมีแค่ไฟล์ต้นฉบับที่ผู้ส่งวาง + PNG ไฟนอลที่ผู้ใช้ Download
ไฟล์ทางเทคนิคของเอเจนต์ทั้งหมดไปอยู่ในโฟลเดอร์ย่อย **`_ไฟล์ทำงาน\`** ของรอบนั้น:

```text
<หมวด>\<ปี>\<รอบ>\
  ต้นฉบับ (docx / jpg / pdf)   ← ผู้ส่ง
  1.png 2.png …                 ← ไฟนอลจาก Canva
  _ไฟล์ทำงาน\
    handover.md                 ← บันทึกส่งต่อ (แดชบอร์ด libdesk อ่านไฟล์นี้)
    layers\ layers.json  *.html *.py  ภาพร่าง ฯลฯ
```

- ห้ามวาง handover.md / layers / html / สคริปต์ / ภาพร่าง ที่ชั้นรอบ · ตัวอ่านรอบงานของ libdesk ข้าม `_ไฟล์ทำงาน\` (ไม่นับเป็นรอบใหม่)
- **`handover.md` ต้องมีหัวข้อ "พรอมท์เจนภาพ"** — ทุกภาพที่เจน (ใช้จริงหรือไม่ก็ตาม) จดทันทีหลังเจน เพื่อให้ผู้ใช้เจนใหม่ได้:
  | ชิ้น | เครื่องมือ | ตั้งค่า (aspectRatio · imageReferences) | ผล (media id มีพื้น → พื้นใส) | ใช้จริง |
  - ตามด้วย **พรอมท์เต็มในบล็อก `text` คัดลอกตรงจากที่ส่งเครื่องมือ ห้ามย่อ/ถอดความ** · พรอมท์ร่างที่ไม่ได้เจน ให้ระบุว่า "ร่าง ยังไม่ได้เจน"
  - ภาพที่ใช้จริง → ลงคลังภาพอ้างอิงสไตล์ในข้อ 3 ด้วย
- หัวข้ออื่นใน handover.md: ตารางช่วงเวลา (ต้นฉบับมา · เอเจนต์ร่าง · ส่งงาน · ขึ้นเว็บ/Facebook) · ภาระงาน/หมวด · ลิงก์ Canva + ช่วงหน้า · ข้อความโพสต์ · คำผิดในต้นฉบับ · บันทึกส่งกลับไปกลับมา · ตาตอนนี้ของใคร

## 1.4 Download ไฟนอลลงโฟลเดอร์รอบ — เมื่อผู้ใช้บอก "โอเค" ในแชต

ผู้ใช้สั่ง 2 ต.ค. 69: ทุกครั้งที่ผู้ใช้โอเคชุดไหน เอเจนต์ Download ลงโฟลเดอร์รอบให้ · ไม่มีคำว่าโอเค = ไม่ Download (การดาวน์โหลดต้องได้อนุญาตต่อครั้ง)

- **Canva MCP ส่งออกไฟล์ไม่ได้** — `read-design` thumbnails ได้แค่ 447px ห้ามใช้เป็นไฟนอล → ใช้ **Claude in Chrome** (Chrome ของผู้ใช้ล็อกอิน Canva อยู่)
1. `read-design` ดูจำนวนหน้า/ชื่อหน้าล่าสุดก่อน (ผู้ใช้อาจลบ/เพิ่มหน้า) — หน้าที่จะเอา = ชุดที่ผู้ใช้โอเค (ทั้งลิงก์ หรือช่วงหน้า)
2. เปิด `https://www.canva.com/design/<id>/edit` → ปุ่ม **Share** (มุมขวาบน — อย่ากดโลโก้/Home มุมซ้าย) → **Download**
3. ตั้ง: File type **PNG** · Size ขนาดจริง (ตัวคูณ 1 — หน้าทำที่ 2160 อยู่แล้ว) · Quality **High** · Select pages **All** หรือ **Custom** ตามชุดที่โอเค → Download
   - ระหว่าง Canva เตรียมไฟล์ แท็บอาจค้าง screenshot timeout — ไม่ต้องกดซ้ำ ไปดู `~/Downloads` แทน
4. ได้ `<ชื่อลิงก์>.zip` ใน `~/Downloads` (ไฟล์ข้างในชื่อ `<ชื่อหน้า>.png`) → แตกเป็น `1.png 2.png …` ตามลำดับหน้า วางชั้นรอบ (ข้อ 1.3)
   - มี PNG เดิมอยู่แล้ว: **ห้ามทับ** ย้ายไป `_ไฟล์ทำงาน\ก่อน-<รอบแก้>\` ก่อน
   - ตรวจขนาดทุกไฟล์ = ขนาดจริง (2160×2160) ไม่ตรง = Download ใหม่
5. จดใน `handover.md`: แถว "ส่งงาน" ใส่วันที่ + บันทึก "Download จาก Canva หน้า … " → ตาต่อไป = `kpi-report` (dry-run ให้ผู้ใช้ดูก่อน)

## 1.2 สไลด์ขึ้น Canva แค่บางหน้า

ต้นฉบับสไลด์ = HTML (ต่อ PDF · ใบงาน · NoteBoard · offline ได้) — ห้ามย้ายทั้งชุดไป Canva (ต้นฉบับ 2 ที่จะไม่ตรงกัน + อัปหลายร้อยชิ้น)
- แยกชั้นขึ้น Canva เฉพาะ ปก · หน้าคั่นส่วน · หน้าภาพรวม (หน้าที่ผู้ใช้อยากจัดเอง) เมื่อผู้ใช้ขอ ลงลิงก์ชื่อเฉพาะของชุดนั้น `ปปปป-ดด <ชื่อเรื่อง> - สไลด์ 1920x1080` (ไม่รวมกับลิงก์เดือน) · รอบแก้เพิ่มหน้าต่อท้ายในลิงก์ของชุดเดิม
- ผู้ใช้แก้ใน Canva แล้ว → `read-design` อ่านตำแหน่ง/ขนาดกลับมาแก้ HTML ให้ตรง (ต้นฉบับยังเป็น HTML)

## 2. แยกชั้นยังไง

| ชั้น (ล่าง → บน) | ทำแบบไหน |
| :--- | :--- |
| สีพื้น | `add_page` ใส่ `background_color` (แก้สีใน Canva ได้ทันที) |
| ลายพื้น (topo / wave / dot grid) | PNG พื้นใสเต็มหน้า แยกจากสีพื้น |
| ของตกแต่ง (วงแหวนมุม จุด เส้น) | PNG พื้นใสทีละชิ้น ครอปพอดีชิ้น |
| แถบโลโก้ / โลโก้ | PNG แยก · พื้นใส `templates/aritc-logo-transparent.png` วางบนพื้นอ่อน/ทำลายน้ำได้ (ห้ามพื้นเข้ม) · แถบขาวใช้ `aritc-logo.png` |
| เงา | PNG แยกจากภาพที่มีเงา (เจาะกลางออก เหลือแต่เงา) ผู้ใช้ปรับ/ลบเงาได้ |
| ภาพหลัก (ปก / ภาพหน้าจอ) | อัปไฟล์จริงความละเอียดเดิม `insert_fill` |
| ภาพประกอบ/สติกเกอร์ | **Canva `generate-image` + `remove-background`** (ดูข้อ 3) |
| ข้อความ | ฟอนต์พิเศษ + ขอบขาว (Pattaya) → PNG แยกบรรทัด · ข้อความที่ผู้ใช้จะแก้บ่อย → ข้อความจริงใน Canva (`add_text`/`replace_text`) แต่ API เลือกฟอนต์ไม่ได้ |

- สคริปต์: วาดแต่ละชั้นใน HTML ที่ขนาดจริง → Edge `--default-background-color=00000000` (พื้นใส) → ครอปตาม alpha → จดตำแหน่งลง `layers.json` → อัปทีละไฟล์ → `insert_fill` ตามตำแหน่ง
- ต้นแบบ: [templates/journal-set.py](templates/journal-set.py) (วาด) + [templates/journal-set-layers.py](templates/journal-set-layers.py) (แยกชั้น)
- ลำดับ `insert_fill` = ลำดับชั้น (ใส่ก่อนอยู่ล่าง)

## 3. ภาพประกอบ — ใช้ AI ของ Canva ไม่วาด SVG เอง

ผู้ใช้ติ (2 ต.ค. 69): สติกเกอร์ที่เอเจนต์วาดด้วย SVG "เหมือนตัดแปะ ดูขาด ๆ ท่อน ๆ" — รูปทรงแยกชิ้น ไม่กลืนกัน
ผู้ใช้มี **Canva Pro** (2 ต.ค. 69) — ให้ Canva วาดภาพประกอบทุกชิ้นที่ไม่ใช่เรขาคณิต

| :--- | :--- |

| ลายพื้นที่ต้องต่อกันได้ (topo, wave, dot grid) · วงกลม เส้น จุด แผงเรขาคณิต | เอเจนต์ (HTML/SVG) — ต้องคุมคาบลาย/ตำแหน่งแม่น |

| ปกหนังสือ / ภาพหน้าจอ / ภาพถ่ายจริง | ไฟล์จริงเท่านั้น ห้ามเจน |

**ขั้นตอน**
1. พรอมท์จาก PR Agent (`aritc-social-post-agent.md` ข้อ 3 — แก่นภาพจากเนื้อหาเล่ม ไม่ใช่ฉากห้องสมุด) แล้วต่อท้ายด้วยโครงนี้:
   ```text
   <motif จากเนื้อหา>, single cohesive die-cut sticker illustration, one unified shape,
   flat vector, smooth rounded shapes, consistent line weight,
   colour palette <hex 3–4 สีจาก [GRAPHIC-SPEC]>, plain solid light grey background, centered, no text
   ```
2. `generate-image` (`aspectRatio: SQUARE_1_1` สำหรับสติกเกอร์) → ดูภาพ ถ้ามีตัวอักษรปน/รูปทรงขาด เจนใหม่ด้วยพรอมท์ที่แก้ ไม่ต้องถาม
3. `remove-background` → PNG พื้นใส (ขอบขาวสติกเกอร์หายไปด้วย — ยอมรับได้)
4. `insert_fill` เป็นชั้นแยก ตามตารางระยะห่างข้อ 4 (วัดขอบที่มองเห็น)
5. **คุมสไตล์ให้ต่อเนื่องทั้งซีรีส์:** งานรอบถัดไปของหมวดเดิมส่ง `imageReferences` = media id ของภาพที่ผู้ใช้ผ่านแล้ว (ตารางด้านล่าง) + พรอมท์ `in the same illustration style as the reference`
6. จดพรอมท์เต็ม + media id ลง `_ไฟล์ทำงาน\handover.md` ของรอบทันที (1.3) · ภาพที่ผู้ใช้ใช้จริงลงตารางนี้ด้วย (ผู้ใช้แก้/เปลี่ยนใน Canva = ดูด้วย `read-design` ว่าเหลือภาพไหน)

## 4. ระยะห่าง (padding / spacing) — ตรวจทุกหน้าก่อน commit

ผู้ใช้ติ: งานกราฟิกมีปัญหาระยะเบียดบ่อยมาก (ต้นกล้าชิดป้ายเดือน · หัวเรื่องชิดแถบโลโก้ · ภาพชิดขอบล่าง)

**หน่วย 24px บนหน้า 2160** (สไลด์ 1920 ใช้ 24px เหมือนกัน · สไลด์ HTML 1280 ใช้ 16px) — ทุกระยะเป็นจำนวนเท่าของหน่วย

| ระยะ | ค่าบนหน้า 2160 |
| :--- | :--- |
| ขอบปลอดภัย (เนื้อหาห้ามเข้าใกล้ขอบกว่านี้) | ≥ 144 (6 หน่วย) · ของตกแต่งล้นขอบได้ |
| หัวเรื่อง ↔ ป้าย/บรรทัดรองที่อยู่กลุ่มเดียวกัน | 48–72 (2–3 หน่วย) |
| ระหว่างกลุ่ม (หัวเรื่องกลุ่ม ↔ ภาพหลัก) | ≥ 96 (4 หน่วย) — ต้องมากกว่าระยะในกลุ่มชัดเจน |
| แถบโลโก้ที่ติดขอบบน ↔ หัวเรื่อง | ≥ 72 |
| ป้ายแคปซูล (pill) | padding ซ้าย-ขวา ≈ 0.5 × ขนาดตัวอักษร · บน-ล่าง ≈ 0.1–0.15 × |
| ช่องไฟรอบภาพในการ์ด | เท่ากันทุกด้าน |

- **วัดจากขอบที่มองเห็นจริง** ไม่ใช่กรอบชิ้น: ภาพจาก AI/สติกเกอร์มีขอบใสรอบ ๆ — ครอปตาม alpha ก่อนวัด
- ระยะในกลุ่ม < ระยะระหว่างกลุ่ม เสมอ (คนอ่านจัดกลุ่มจากระยะ)
- จัดกึ่งกลางตามแนวนอนด้วยค่ากลางหน้า (1080) · แนวตั้ง: ระยะบนสุดกับล่างสุดใกล้เคียงกัน
- ตรวจด้วย `scripts/check_layers.py <layers> --pages "title,chip,sticker|num1"` — แจ้งชิ้นล้ำขอบปลอดภัย · ซ้อนกัน · ห่าง < 2 หน่วย · ต้อง "ผ่าน" ก่อน commit แล้วดูภาพย่อจริงอีกรอบ
- Edge ในเครื่องนี้คืนค่าก่อนเขียนภาพเสร็จ — สคริปต์เรนเดอร์ต้องรอไฟล์ (`wait_file()` ใน `templates/journal-set.py`)
